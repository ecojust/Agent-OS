# 兼容性策略与验证矩阵

## 1. 目标与范围

Agent OS 采用兼容性优先的路线，尽量让近五年发布的手机能够使用 Agent 能力。以 **2026-10-26** 为本轮规划基准，重点覆盖 **2021-10-26 至 2026-10-26 上市**的 Android 手机；后续版本滚动更新目标窗口，并保留已公布设备的历史验证记录。

上市时间用于安排测试优先级，不能替代实际系统版本、可用权限、硬件资源和厂商行为检查。当前尚无已验证机型，不把目标范围标记为兼容保证。

首版默认**不插实体 SIM 卡、不启用 eSIM，通过 Wi-Fi 使用**。蜂窝通话、短信、移动数据及专门的来电中断处理不属于首版功能和验收要求；发布说明须标明这一范围。Wi-Fi 应用仍可能出现网络语音或视频来电，首版不提供 Agent 自动接听或专门中断子系统，沿用通用窗口变化、用户接管、锁屏和撤权保护。具体执行规则见[设计规则](DESIGN_RULES.md)。

无卡是使用场景，不是删减 Android 兼容底座的理由：保留标准电话组件与接口，不伪造硬件能力，也不为缩小首版功能范围跳过平台套件中实际适用的兼容要求。

### 两种交付方式

| 方式 | 兼容目标 | 必要条件 |
| --- | --- | --- |
| 可安装执行器 APK | 尽量覆盖目标窗口内的现有 Android 手机，保留用户当前系统 | Android 11/API 30 或以上；用户能够按系统规定启用所需能力；具体应用任务通过验证 |
| Agent OS 系统镜像 | 为经过适配的参考手机提供更完整的系统集成 | 机型启动链、内核、驱动、厂商接口和恢复方式明确，并通过真机验证 |

完整定制系统仍是项目目标；广泛覆盖现有手机由 APK 模式优先承担。安装 APK 不改变手机的 Android 版本，不要求 Root 或解锁 Bootloader。刷机镜像单独维护设备支持列表，不以 APK 能运行推断系统镜像也可刷入。

目标窗口内但当前系统低于 Android 11 的设备，首版明确列为不支持，调查可升级情况及实际需求后再评估降低最低版本，不在未经测试时宣称已覆盖。原生非 Android 应用生态的系统也不因使用 ARM 芯片而自动纳入支持范围。

## 2. 版本与架构决策

| 项目 | 策略 |
| --- | --- |
| APK 最低版本 `minSdk` | 维持 Android 11/API 30，核心能力使用该基线内可用的公共 API |
| APK 编译与目标版本 | 随经过验证的稳定 SDK 更新，并适配对应行为变化；不靠降低 `targetSdk` 绕过系统限制 |
| Android 11—17 | 纳入当前版本测试矩阵，新功能按运行版本和能力启用；尚未测试的组合保持未验证状态 |
| APK 处理器架构 | 核心优先使用 Java/Kotlin 与平台 API，不默认依赖本地模型或原生 `.so`；面向实际运行 32 位或 64 位 Android 的设备分别验证 |
| 原生依赖 | 后续如引入，明确支持 ABI、内存页大小及安装包内容，并验证；不能只根据芯片型号判断用户空间 ABI |
| 系统镜像 | 首版 ARM64；AOSP 基线根据可维护的稳定源码、目标机型驱动和接口兼容性确定，暂不锁定 Android 11 或 17 |
| 系统分支 | 优先维护一个经过验证的主线；新增旧版本或机型分支必须明确维护资源与更新策略 |

适配新 Android API 时，将新版实现隔离在平台适配器内，完成版本与能力检查后再加载或调用，避免低版本启动时解析不存在的类或方法。

兼容旧系统与提供旧系统安全更新是两项不同工作。APK 不负责修补厂商固件；系统镜像则需要明确自身补丁基线、更新和恢复责任。不能以取消保护、忽略证书错误或绕过安全窗口来换取兼容性。

## 3. 能力探测与分级运行

首次运行展示设备条件与功能可用性，任务启动前再次检查授权、服务连接和屏幕状态。探测以系统报告和实际接口结果为依据；涉及操作或截图的验证在用户明确启动的测试或任务中进行，不在后台自动操作其他应用。

### 功能能力表

| 能力 | 优先实现 | 条件不满足时 |
| --- | --- | --- |
| 应用发现与启动 | 包管理器可见范围、授权应用启动入口 | 明确缺失或不可启动，不假定可枚举所有应用 |
| 结构化操作 | 已授权窗口的 Accessibility 节点与动作 | 使用应用公开接口；其他回退仍需满足可观察性和授权条件 |
| 坐标操作 | 绑定当前界面版本的受控手势 | 有遮挡、范围不明或版本失效时拒绝执行 |
| 截图 | 在适用版本优先使用按窗口截图 | 较旧版本仅在能确认授权范围、遮挡和敏感内容时裁切显示截图，否则禁用图像观察 |
| 无图像模式 | 使用界面节点和公开接口进行观察 | 模型无视觉能力或截图不可用时继续可验证任务；无有效观察路径的任务交由用户处理 |
| 任务控制条 | 用户可见且能独立暂停、停止 | 无法显示控制入口时不运行任务 |
| 密钥保护 | 系统密钥库及加密配置 | 不退回明文保存；提示修复配置或将依赖该能力的启动步骤判为不可用 |
| 模型连接 | HTTPS 服务，或明确配置的局域网服务 | 报告网络、认证或协议问题，不跳过证书验证 |

Android 11 已提供 Accessibility 显示截图接口；Android 14 提供按窗口截图等后续能力。实际是否可用还受到服务声明、授权、窗口保护和厂商实现影响，不能只凭 API 版本标记可用。

密码字段、安全窗口以及系统限制披露的敏感内容，在所有模式中保持同样的保护边界。节点访问受限时，不使用截图或坐标路径绕过这一限制。

### 运行等级

- **标准能力**：核心控制、结构化操作和按需图像观察路径均通过验证；截图仍需用户确认。
- **文本与结构模式**：关闭图像能力，依靠节点和公开接口完成可观察的任务。
- **有限支持**：只允许明确可用且可验证的工具，任务开始前展示限制。
- **不可运行**：系统版本不足、执行服务不可用、无法显示停止入口或必要保护条件不成立。

设备条件不满足某个可选能力，不应导致整个应用无法启动；核心执行条件不成立时则不启动任务。

## 4. 低资源设备策略

- 默认使用用户配置的模型服务，不要求手机下载大模型或具备专用 AI 芯片。
- 一个前台任务、一个设备写操作通道；不并行操作多个应用界面。
- 限制节点数量、文本长度、模型上下文、日志条数和任务总预算。
- 截图按需生成、限制像素与编码体积，发送或取消后及时释放位图和硬件缓冲。
- 使用事件驱动和有界等待，避免常驻高频轮询；发生内存压力时优先释放图片和可重建缓存。
- 压力测试覆盖典型 2—4 GB 低内存样本及主流设备，不在测试前宣布最低内存或流畅度保证。

## 5. 测试矩阵

以下是测试计划，不代表这些组合已经通过。

| 维度 | 计划覆盖 |
| --- | --- |
| 系统/API | Android 11/API 30、12/API 31、12L/API 32、13/API 33、14/API 34、15/API 35、16/API 36 与相关季度版本、17/API 37 |
| 厂商实现 | 不同厂商系统与接近 AOSP 的实现，重点覆盖无障碍授权、侧载限制、后台管理和窗口行为 |
| 上市时间 | 目标窗口早期、中期和近期机型，兼顾原生系统与升级后的系统 |
| 芯片与 ABI | 多个芯片厂商、实际 32 位与 64 位用户空间；模拟器架构单独记录 |
| 资源与显示 | 低内存与主流内存、大小屏、刘海/挖孔、不同显示缩放和字体大小 |
| 界面与输入 | 横竖屏切换、软键盘遮挡、手势与三键导航、多窗口和悬浮界面 |
| 生命周期 | 亮屏/锁屏、用户接管、窗口变化、服务断开、用户撤权、进程回收、应用更新、重启后不自动继续任务 |
| 模型与网络 | 无实体 SIM、无启用 eSIM，验证 Wi-Fi 连接/切换、文本工具模型、视觉模型、超时、断网、限流、认证错误及不合法工具参数 |
| 应用任务 | 不同应用版本、公开接口、标准控件、自绘控件、跳转到未授权应用和受保护页面 |

模拟器用于覆盖 API 行为和可重复的测试应用操作；真机用于验证厂商差异、授权流程、资源压力和日常任务。首轮真机样本建议跨至少三个系统厂商、两类芯片平台和三个上市时间段，具体数量依可获得设备确定，不以样本通过推断整个平台或品牌全部兼容。

### 每次验证的记录

记录设备完整型号与地区变体、实际 ABI、系统版本与构建号、安全补丁日期、执行器版本、应用版本、模型标识、无卡/eSIM 停用状态、Wi-Fi 条件、测试日期、功能结果、限制和复现步骤。不得将模型密钥和实际个人内容写入兼容性记录。

支持状态使用以下四类，并分别记录“APK 可安装”“核心任务可用”“可选能力”和“ROM 可刷写”结果：

| 状态 | 条件 |
| --- | --- |
| 已验证 | 指定设备与版本组合完成必测项，并公开结果范围 |
| 有限支持 | 核心路径或部分任务通过，但存在明确功能限制 |
| 未验证 | 仅理论条件满足或尚无实测结果 |
| 不支持 | 明确缺少必要条件，或已确认阻断性问题 |

原厂系统更新、执行器关键升级或目标应用界面变化后，应重新验证受影响的组合。没有完整设备样本和测量方法时，不发布“覆盖率 95%”一类数字。

## 6. 验收与发布条件

1. 每个计划支持的 API 版本通过最低启动、模型配置、错误处理和核心协议检查。
2. 低版本系统不会因调用新 API 启动失败；新版本的权限和生命周期规则已适配。
3. 真机完成选定任务，记录实际目标状态；“接口返回成功”不算目标完成。
4. 暂停、停止、锁屏和撤权后不再提交后续动作，迟到回调不能恢复旧任务。
5. 不支持截图或视觉模型时，结构化任务仍可运行；没有可观察路径时准确报告限制。
6. 保护规则在降级模式同样有效，密码、受保护内容和授权范围外的信息不进入模型上下文。
7. 发行说明列出实际测试范围和限制。未验证机型保持未验证标记，不升级成整品牌支持声明。
8. 第三方应用的安装更新和日常核心流程按[应用兼容性验收](APP_COMPATIBILITY.md)独立通过；Agent 自动操作能力另列结果。
9. 按[性能方案](PERFORMANCE.md)检查 Agent 对应用启动、帧时间、CPU、内存与能耗的影响；系统镜像还需完成参考系统对照。

## 7. 系统镜像路线

系统镜像优先选择可解锁且资料完整的 ARM64 参考手机，根据该机型稳定可用的内核、厂商接口与驱动确定 AOSP 基线。版本选择同时考虑可维护性与兼容性，不为旧硬件无条件退回缺少维护的系统分支，也不强制所有设备升级至 Android 17。

GSI 仅作为满足 Bootloader 解锁、完整 Treble、ABI、分区及厂商接口条件设备的评估路线。启动成功之后仍需测试首版范围内的 Wi-Fi/蓝牙、相机、指纹、功耗与恢复流程；不能据此宣称蜂窝业务已验证。相同芯片、品牌或上市年份均不能替代机型验证。

对不能刷入定制系统但 APK 模式通过验证的手机，保留 APK 使用路线，不要求用户更换系统才能使用已支持的 Agent 功能。
