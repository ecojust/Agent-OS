# Agent OS 设计规则

本文将已确定的产品选择细化为实现契约，包含当前原型与后续系统阶段目标。当前 Android 执行器的已实现能力、自动化验证与限制见 [IMPLEMENTATION.md](../IMPLEMENTATION.md)，尚无系统镜像或真机通过结果。性能数值以 [PERFORMANCE.md](PERFORMANCE.md) 为准，设备及应用支持范围以各自验收记录为准。

## 0. 首版使用场景

- 默认设备不插实体 SIM 卡、不启用 eSIM，通过 Wi-Fi 访问用户配置的模型服务。
- 手机亮屏、已解锁，用户在手机内发起任务并能看到操作过程；首版仅操作当前个人资料中的授权应用。
- 蜂窝通话、短信、移动数据以及专门的来电中断与恢复流程不属于首版功能或验收要求，也不为此申请电话、通话记录或短信权限。
- 不新增专门的电话、通知或闹钟处理子系统。系统窗口变化、锁屏、撤权及用户接管仍按下面的通用执行条件处理，避免使用过期目标；不主动关闭弹窗或屏蔽正常通知。
- 无卡是使用范围约定，不是删除 Android 标准电话组件、改写第三方应用行为或阻止软件启动的理由。插卡后的蜂窝能力不因此被标记为已验证。
- 需要本机 SIM、短信或其他外部服务的应用流程如实记录依赖与限制，不能宣称无卡环境已通过。不得在测试后移除失败样本来提高兼容率。

## R1. 用户接管与执行控制

同一设备同一时刻只有一个 Agent 前台任务和一个设备写操作通道。用户始终可以暂停、接管或停止，控制入口不等待模型或网络响应。

| 操作 | 确定行为 |
| --- | --- |
| 暂停 / 接管 | 立即使当前执行代次失效，取消待执行动作和在途模型请求；保留本次任务目标，不继续操作 |
| 继续 | 用户主动触发，保留原 `taskId` 并递增执行代次，重新观察，旧动作和旧确认均不可复用；已消耗的时间、调用次数和失败预算不重置 |
| 停止 | 结束会话，释放任务资源；旧请求、回调和工具调用永远不能恢复执行 |
| 已提交动作 | 如实记录可能仍在完成；停止不保证撤回已经发送的消息、已经点击的按钮或系统已接受的手势 |

APK 阶段不承诺可靠观察所有物理触摸，不使用全局输入拦截来实现“碰屏即停”。明确的接管入口必须可用；观察到非预期的应用切换、焦点或目标内容变化时，在下一次提交动作前暂停或重新观察。不能把无障碍事件缺失当作用户没有操作的证据。

恢复后不得自动抢回焦点或返回旧应用。用户选择继续任务后，也需依据当前界面重新规划。

设备写入区分本地准入与系统接受：耗时校验结束后，执行线程取得绑定原执行代次的单次提交凭据；同一任务最多一项在途，停止后不能取得新凭据。凭据不表示系统已经接受操作。调用外部 API 前仍复核取消状态，但本地检查与系统调用不是原子事务；已经进入该窄提交阶段的动作可能仍在完成，停止界面须提示用户核对。停止不等待远端调用，也不能替执行线程提前释放凭据；由原线程在 `finally` 中结算，旧结果不得恢复任务或触发重发。

## R2. 通用执行条件与界面失效

首版不实现针对每一种外部中断的业务流程，只保留所有设备动作都需要的条件检查。

| 可观察变化 | 处理规则 |
| --- | --- |
| 锁屏、熄屏、执行服务断开、关键权限撤回、用户或资料切换 | 停止任务，旧会话失效；条件恢复后不自动继续 |
| 用户主动接管、无法确认的前台跳转、目标被未知窗口遮挡 | 暂停并说明原因，不能点击穿透、自动关闭遮挡或操作未授权窗口 |
| 旋转、显示缩放、键盘或目标窗口几何变化 | 使相关节点与坐标版本失效，重新观察；无法确认目标时暂停 |
| Agent 已提交动作导致的预期页面变化 | 重新观察并验证结果，然后才允许下一步 |
| 不遮挡目标且不改变执行条件的普通通知或后台事件 | 不自动接管处理；仅在影响当前观察与目标时更新对应版本 |

界面版本绑定当前用户资料、应用、窗口和布局/目标状态，不把每一帧动画都当作新版本，也不能仅用截图像素未变化证明目标仍有效。自身可信控制条或确认界面出现时不得制造无限失效循环；返回目标界面后仍要复核目标应用和动作条件。

通用检查无法保证发现所有外部变化。实现必须保留观察与提交之间的最终校验，并在无法可靠定位时返回限制，不能盲目沿用旧坐标。

## R3. 授权与确认绑定

- 应用范围由用户在本机选择，读取和操作分别受该范围约束；模型和被读取页面不能修改范围或关闭确认。
- 长期应用选择绑定用户资料、包名和安装身份。卸载重装、签名身份异常或资料改变后重新授权；正常签名继承的更新重新检查能力与当前界面，不继承旧动作确认。
- 默认逐步确认。用户关闭逐步确认后，仅允许范围内、当前支持且可以验证的普通操作连续执行；截图外发仍单独确认。首版不将付款、账户删除等高影响流程列为支持任务。
- 单次确认绑定 `taskId`、执行代次、资料、应用、工具、规范化参数、相关界面版本和模型服务配置版本。确认只能消费一次，默认 60 秒有效；超时后暂停，不能反复弹窗催促或自动同意。
- 目标、动作参数、接收数据的模型服务、授权范围改变，或任务暂停、停止时，旧确认失效。确认界面展示的动作与最终提交动作必须来自同一个不可变请求。
- 拒绝一个动作后，不得改用坐标、其他工具或另一应用绕过；只有用户明确修改目标或重新授权后才能重新规划相关行为。

确认时限是首轮产品默认值，运行中使用单调时钟判定；修改该默认值需更新规则及回归用例，不能由模型自行延长。

### 连续操作的分阶段开放

第一阶段只开放用户明确选择的“连续导航”：`launch_app`、`scroll`、`home` 可以省去逐次人工确认，但仍必须经过原有授权、完整观察、窗口版本、配置许可、控制条和最终派发校验。每次写操作后重新观察，不能一次直通模型给出的多项写操作。

`back` 可能触发应用提交或丢弃表单，因此与 `click`、`type_text` 一样继续逐次确认。未知或未来工具没有自动豁免；工具名、页面关键词或模型声称“安全”均不能建立新的执行权限。截图披露和坐标手势继续按各自能力条件验收，不随导航模式开放。

模式使用单独的 `executionMode` 配置，默认 `CONFIRM_ALL`；只有用户明确选择 `CONTINUOUS_NAVIGATION` 才改变上述三种工具的确认决策。旧配置缺少该字段时，即使旧确认布尔值为 false，也不启用新能力；未知模式拒绝读取且保留原数据。模式保存使旧配置许可失效。该阶段不等于任意普通控件均可免确认；进一步开放需要具体、可验证的动作契约及回归证据。

连续导航遇到截断观察、敏感字段或已知高影响页面时拒绝自动执行；这些标记只用于拒绝，不能据其缺失推断任意操作安全。未授权前台不读取内容，自动启动应用仅允许以本应用或系统解析的默认桌面的普通应用窗口为来源；其他未知前台或窗口遮挡由用户接管。模式参数必须与当前有效的已保存配置一致，不能由调用者临时提升。

## R4. 工具协议与执行一致性

首版内部协议主版本为 `1`，模型网关将服务端工具调用转换为同一份本机契约。执行器建立会话时报告协议版本和可用能力；主版本不兼容时拒绝执行，不静默猜测字段含义。

| 字段 / 结果 | 规则 |
| --- | --- |
| `protocolVersion`、`taskId`、`callId` | 版本、会话和调用唯一标识；不同任务不能复用授权或调用结果 |
| `executionEpoch`、`profileId` | 分别绑定本次执行代次与资料；由可信本机上下文设定并验证，不能由模型任意选择 |
| `tool`、`arguments` | 工具白名单及对应参数 schema；限制字符串、列表、数值范围和未知字段，不接受任意脚本 |
| `expectedRevision` | 依赖已有观察的读写必须匹配对应版本；旧节点、旧窗口和旧坐标不可重用 |
| 动作结果 | 分别报告是否提交、是否被系统接受以及验证状态；目标状态可为已验证、部分完成、未验证或结果未知 |

首次或用于刷新当前状态的 `observe` 不要求已有 `expectedRevision`；通过可信会话、执行代次、资料和授权范围校验后生成新版本。随后依赖该观察的动作必须使用并匹配该版本，不能将刷新观察当作绕过动作校验的通道。

执行器负责界面条件、权限、取消及参数校验，不以模型自称“安全”或“已完成”替代这些检查。应用公开接口也经过同一授权与结果验证路径。

同一 `callId` 与相同请求重复到达时，返回已有结果或处理中状态，不再次提交设备动作；同 ID 不同参数直接拒绝。写操作超时、崩溃或结果丢失后，不能证明未执行时报告结果未知，先观察或交由用户核对。设备 UI 操作不提供跨应用事务或“恰好一次完成”的保证。

错误至少区分：`INVALID_ARGUMENT`、`UNSUPPORTED_VERSION`、`CAPABILITY_UNAVAILABLE`、`PERMISSION_DENIED`、`STALE_OBSERVATION`、`APPROVAL_EXPIRED`、`TASK_PAUSED`、`TASK_STOPPED`、`TIMEOUT`、`OUTCOME_UNKNOWN`、`BUDGET_EXCEEDED`。分别给出可读原因和允许的下一步，不把所有失败都解释为可重试。

工具清单、schema、确认展示、执行校验和测试样例使用同一份版本化定义。完整的机器可读 schema 是 M1 实现交付物；当前工具可用性与验证状态以实现记录为准。

## R5. 模型、网络与任务预算

- 模型地址、模型与密钥由用户设置；连接成功、工具协议可用和图像能力分别验证。切换服务或模型前结束当前任务，并建立新的配置版本。
- 不自动切换到其他提供方，不把密钥带到跨源重定向地址；公网 HTTPS 校验失败时返回错误，不跳过证书校验。明确配置的局域网 HTTP 按既有传输提示处理。
- 网络请求、响应解析和上下文裁剪在工作线程完成；流式响应未形成完整、通过校验的动作前不提交设备操作。
- 应用界面、网页、文件和工具结果是任务数据，其中的指令不能覆盖用户目标、应用范围或本机规则；上下文裁剪也必须保留这些边界。

| 预算 | 首轮默认规则 |
| --- | --- |
| 连接等待 | 每次请求最多 10 秒 |
| 单次模型请求 | 从发起起最多 90 秒；流式返回连续 30 秒无数据视为超时，持续有数据也不延长总时限 |
| 模型自动重试 | 仅在传输层能确认请求未发送，或收到服务端明确拒绝且可重试的限流响应时，最多重试 2 次；计入同一请求总时限及任务预算。已发送后响应丢失等情况不自动重发 |
| 界面观察稳定窗口 | 只对 `observe` 的 `STALE_OBSERVATION` 自动重新观察：从首次尝试起最多 2 秒、最多 6 次，每次使用独立调用标识；等待按 125、250、375、500、625 ms 递增并受剩余窗口与任务活动预算约束。暂停或停止立即打断等待；其他错误不重试。窗口限制后续读取的发起，已进入平台的同步读取仍由其自身超时与取消路径结束；不会因此重放任何写操作 |
| 单次任务 | 默认最多 30 个模型轮次、100 个工具调用、10 分钟活动时间；所有重试也计数，达到任一上限停止并给出部分结果 |
| 暂停 / 等待确认 | 不进行后台任务计算；暂停默认最多保留 10 分钟后结束会话，确认另受 60 秒时限约束；等待时长单独报告，不计入活动时间 |
| 费用与 token | 用户可以设 token 上限；只有具备计价信息时展示费用估算，缺少用量时标为未知。不能承诺服务端实际账单精确受本机估算限制 |

用户可以在任务启动前调整普通任务预算，修改后需展示生效值；模型不能自行增加预算。暂停后继续保留同一任务已消耗的预算，不重新计算一份完整上限。安全边界、单次动作确认和停止规则不随预算调整而放宽。对没有可靠 tokenizer 的服务使用保守估算，并注明与服务端统计可能不同。

## R6. 数据、密钥与清理

| 数据 | 保存与清理规则 |
| --- | --- |
| 模型配置与密钥 | 使用本机加密存储与 Android Keystore；配置保留至用户删除，密钥不进入日志、任务上下文、普通导出或系统云备份 |
| 应用范围与偏好 | 按资料隔离保存；导入偏好不自动恢复执行授权，仍需用户确认和系统实际授权 |
| 对话、观察、动作内容与截图 | 默认仅存在于当前任务内存；结束、停止或保留时限届满后释放运行上下文，不默认生成历史文件；本轮结果可暂留当前界面，清空、新任务或进程退出后移除 |
| 诊断事件 | 默认内存有界队列，最多 200 条，仅记录动作类别、状态、时间和错误码；可手动清空，进程退出后不恢复 |
| 诊断导出 | 用户查看脱敏内容后主动导出；导出的文件由用户管理，不承诺撤回已分享副本 |

读取加密配置失败或 Keystore 密钥失效时，不覆盖原配置、不降级为明文；明确提示重新配置，并在用户选择重置后清除不可用副本。重新安装、换机或系统恢复不保证原密钥可用。

已发送到模型服务的数据受该服务的数据政策约束。本机清理只能清理本机持有的数据，不能宣称同步删除服务方副本。

## R7. 用户资料与权限边界

- 首版只执行当前个人资料中的任务，不提供工作资料、访客或其他 Android 用户的自动操作能力。
- 应用身份不能仅使用包名，必须包含用户/资料标识；观察缓存、授权、密钥和诊断同样隔离。
- 用户切换或资料失效时停止任务；不得静默切回原用户，不使用跨用户权限规避限制。
- APK 使用用户明确启用的公共能力；后续 AOSP 桥接单独校验调用 UID、签名权限、会话及用户身份，使用最小 SELinux 权限。
- 模型网关不因系统集成而获得任意系统权限。新增系统工具先定义能力、授权、参数和验收，再进入可用工具列表。

## R8. 统一交互与可访问性

- 使用原生界面，统一浅色、深色和跟随系统主题；语义颜色、间距、字体与组件状态集中定义，操作图标使用矢量资源。
- 常规触控目标至少 48 dp；普通文字对比度目标至少 4.5:1，大字至少 3:1，状态不能只靠颜色表达。
- 支持系统字体缩放、横竖屏、安全区域和软键盘；重要操作在放大字体或小屏下仍可到达。
- 执行条始终显示当前任务状态与暂停/停止入口；不覆盖必要的系统导航，不通过透明区域截获无关触摸。无法维持可用控制入口时不继续任务。
- 明确区分观察中、等待模型、等待确认、执行中、暂停和终止原因。没有真实进度时显示阶段和耗时，不编造百分比。
- 确认页展示目标应用、动作摘要和必要参数；不得在确认界面披露密码或完整密钥。失败提示包含可执行的恢复步骤。
- 支持读屏标签、合理焦点顺序与减少动态效果；与系统读屏等服务的共存通过实测确认，不为了 Agent 自动关闭用户已有的辅助功能。

## R9. 更新、迁移与恢复

APK 更新、配置迁移和 ROM OTA 使用不同流程：

- 发布 APK 维持合法签名连续性；受控更新前结束任务，外部安装或进程被系统终止后也不自动恢复旧动作。新版本启动先验证配置版本，再开放执行。
- 配置迁移先保留原数据，写入新副本并验证后原子切换；失败时保留原数据并禁用依赖该配置的执行，提示恢复或重新配置。不能默默清空密钥和授权。
- 遇到较新的、不认识的数据格式时不覆盖；旧版本不保证能读取新版数据，不通过强制安装降级冒充可恢复迁移。
- ROM 更新需核对具体机型、签名、镜像完整性、可用空间及设备要求；更新过程不运行 Agent 任务。
- 每个系统镜像发布前提供经过验证的失败启动恢复流程，并说明数据保留、备份及可能清除数据的步骤。是否支持 A/B 更新和版本回退由设备条件决定，遵守反回滚约束，不承诺通用“一键回滚”。

发布签名私钥不进入仓库或应用；正式签名与开发签名分开管理。更新信任链、密钥轮换和平台补丁不能由模型输出决定。

## R10. 维护、交付与规则变更

- 每个正式支持的 ROM 机型发布前登记完整型号/地区变体、维护起止日期、维护责任、系统与厂商补丁来源及发布节奏；字段未确定时只能标为试验或预览支持。
- 默认每月检查平台、内核、WebView 与引入依赖的更新，记录可修复、受上游限制及待验证事项。检查频率不等于每月都能获得厂商补丁，不虚构设备补丁日期。
- APK 最低系统版本、协议主版本、数据格式或维护范围改变时，发布前说明影响与迁移路径，不能静默停止支持。
- 停止维护时明确最后支持版本、已知问题和可用恢复资料；无法保证未来安全或兼容的组合不继续标为当前标准支持。
- 构建固定依赖版本，保留源码提交、构建环境、产物校验值、必要许可证和验证结果。正式发布使用通过检查的同一份构建产物，不能只验证调试包。
- 每条规则关联正向、拒绝和恢复用例。协议/状态机可自动测试，手机硬件、资源开销、系统镜像恢复与真实应用必须保留对应实测证据。

本文件的规则变更需说明原因、影响模块、兼容/迁移方式及回归用例；不能通过修改文档把尚未验证的行为标记为完成。[应用兼容性](APP_COMPATIBILITY.md)、[设备兼容性](COMPATIBILITY.md)与[性能预算](PERFORMANCE.md)共同作为发布约束。

## 验收安排

| 阶段 | 规则落地要求 |
| --- | --- |
| M0 设计基线 | 本文作为默认设计决策；范围与未实现状态明确 |
| M1 APK 原型 | R1—R8 的契约、schema、状态和关键异常用例实现；无卡 Wi-Fi 任务闭环通过，不能用网络连通替代设备动作验证 |
| 首次正式 APK 发布 | R9 的签名/迁移和 R10 的发布证据到位；应用、设备与性能验证按声明范围通过 |
| M3 ROM 发布 | 增加 R7 特权隔离、R9 镜像恢复和 R10 每机型维护信息；蜂窝能力仍未纳入首版支持声明 |

最小回归场景包括：确认期间目标改变、暂停时模型晚到、重复调用、写操作结果未知、权限弹窗遮挡、旋转与键盘变化、锁屏与撤权、Wi-Fi 断开、配置迁移失败和密钥不可恢复。无需为这些用例插入 SIM 卡或新增专门的来电中断流程。
