## 1. 目标与约束

Agent OS 的性能目标是：保留正常手机使用体验，Agent 只在任务需要时消耗额外资源，模型或网络变慢时控制界面仍能及时响应。第三方应用在标准 Android 环境中原生运行，不经过 Agent 或模型代理；Agent 故障不能阻断应用启动、输入、媒体播放和系统导航。

本文是设计和验收计划，尚无真机测量结果。以下数值是首轮工程预算，不是已达到的性能数据或适用于所有设备的保证。参考机型确定后，先测量基线并公开必要调整，在发布验收前冻结预算，不通过临时放宽指标掩盖回归。

首版以**无实体 SIM 卡、无启用 eSIM、使用 Wi-Fi**为统一测量场景。蜂窝通话、短信、移动数据和专门来电中断流程不列为首版性能必测项，也不新增专门中断子系统；锁屏、用户接管、窗口变化和撤权等通用保护仍执行[设计规则](DESIGN_RULES.md)。保留标准 Android 电话组件，不通过删减兼容底座获得性能数据。

## 2. 进程与调用边界

| 组件 | 运行方式 | 性能与故障边界 |
| --- | --- | --- |
| 对话与任务控制界面 | 原生界面，状态通过异步消息更新 | UI 主线程不等待模型、网络或设备操作完成；暂停与停止独立可用 |
| Agent Runtime | 逻辑独立、任务驱动；是否单独进程以隔离收益和实测内存成本决定 | 模型请求、上下文处理与任务计算在工作线程执行；任务结束释放连接与大对象 |
| 观察与执行适配器 | 遵守平台线程要求的有界读写 | 不做高频全量遍历；读写有超时、版本校验和取消检查 |
| 后续 AOSP 特权桥接服务 | 小接口、有限调用、最小权限 | 不在系统关键线程做模型推理、图片编码或网络请求；客户端失效时终止会话 |
| 系统与第三方应用 | 保持标准 ART、框架、图形和媒体执行路径 | 正常应用运行不依赖 Agent 在线；资源不足时先收缩 Agent 可选工作 |

“模块独立”不等于每个模块都建立常驻进程。APK 阶段优先少量工作线程；在需要单独进程隔离时衡量进程启动、IPC 和额外内存。系统集成只将确有需要的受控能力放入特权服务，不把整个 Agent 放入 `system_server`。

禁止在系统应用启动、输入分发、绘制、包管理或常规 Binder 调用的关键路径中加入同步模型请求。Agent 失效时，用户仍可回到桌面并手动使用应用。

## 3. 调度与取消

- 同一设备只有一个 UI 写操作通道。网络和计算可以异步进行，不能并发点击不同应用。
- 操作调度、网络请求和图片处理分别设有界队列，不通过无限线程或无限排队提高吞吐。
- 用户停止、锁屏和服务失效属于高优先级控制消息，不排在模型响应、截图压缩或任务日志之后。
- 停止先使会话失效，再取消请求和待执行工作；动作实际提交前再次检查会话与取消状态。已经交给系统的动作可能仍在完成，需如实记录。
- 暂停不再发起后续动作；恢复时重新观察并丢弃旧动作与旧确认。
- 没有任务时不截屏、不构建界面树、不请求模型、不进行高频轮询，也不申请用于维持 Agent 空闲运行的持续唤醒锁。
- 等待页面变化优先使用相关事件与稳定性判断，事件合并设置最大等待时间；不得在持续动画页面无限等待或无限观察。

## 4. 观察、图片与上下文

| 对象 | 初始资源上限与策略 |
| --- | --- |
| 待处理观察 | 最多保留一个正在生成的快照和一个最新待处理请求；合并重复事件 |
| 界面结构 | 默认至多 300 个节点、单字段 160 字符、序列化快照 64 KiB；超限时标记截断，不能推断不存在的控件 |
| 事件合并 | 按场景以约 100—250 ms 合并事件；调度策略可调，停止信号不参与该等待 |
| 缓存 | 只复用版本匹配的只读数据；应用、窗口、旋转、键盘或敏感状态变化，以及暂停恢复均使相关缓存失效；写操作仍检查当前界面与授权 |
| 截图 | 按需请求，默认长边不超过 1280 像素且总像素不超过约 1 MP；需要更高精度时显式评估设备能力 |
| 图片工作集 | 默认只处理一帧，图像缓冲预算 24 MiB、单张编码数据目标不超过 1 MiB；超过预算优先降采样或禁用可选图片路径 |
| 模型上下文 | 依据模型上下文限制和任务预算裁剪；优先保留用户目标、最新观察、授权边界和必要结果，不反复发送完整历史图片 |
| 日志 | 有界记录，例如最近 200 条脱敏事件；合并重复状态，诊断导出由用户明确触发 |

平台截图返回的原始全屏缓冲也计入峰值；请求前按尺寸和格式保守估算，如果捕获阶段本身超过图像预算，应改用可用的按窗口路径或关闭图像能力，不能只统计缩小后的图片。若平台实际返回的缓冲超出估算，及时释放、记录真实峰值并禁用该路径，不能因为随后释放就算作未超限。编码、序列化和网络发送都放到工作线程，避免同时持有位图、多个编码副本和冗余请求体。

当前图片审阅与模型请求已实现进程共享的已知容量准入：PNG 自有编码、校验输出缓冲、明确分配的解码临时缓冲、预览像素预约，以及至多 4 MiB 的请求 UTF-8 正文。请求先有界计算长度，再预约并写入精确容量，不构造整份 JSON 临时字符串；两遍校验字节数与摘要一致。关闭图片所有者不会提前归还仍被读取者或待消费结果使用的额度；已展示图像解除 View 引用后只释放应用侧所有权。取消网络 Future 不代表原工作线程退出，在途正文等原线程结束后才擦除和归还，取消回调不做大缓冲清理。

任务图片附件直接从不可变 PNG 分块写入请求，不创建完整 Base64 中间字符串。旧工具 dataURL 入口的临时解码数组和固定11 KiB的编码暂存也在分配前预约；原图在正文编码后释放，网络线程仅持有最终正文。该路径已通过223项核心测试；独立合成图能力探测仍使用旧字符串路径，平台截图尚未接入，不能将此项优化称为全流程内存验收。

此计数不包含调用者源数组、现有 dataURL 字符串、JSON 对象、编码器内部缓冲、HTTP 内部缓冲、GC、平台 codec 或 RenderThread/GPU，不能据此声称上述 24 MiB 全流程实际峰值已达标。目标仍需完整捕获、附件传输接线和设备测量验证。


低资源降级不能省略授权检查、界面版本校验或敏感内容处理。无法在预算内保留可靠观察时，报告受限能力并让用户接管。

## 5. 初始性能预算

测量范围为 Agent 功能引入的工作。内存按相关进程合计 PSS 记录，并另记 Java、Native、图形缓冲、RSS 和峰值，不把这些重叠指标再次相加；CPU 用“占满一个逻辑核心为 100%”计量，增量按配对窗口的 CPU 累计秒差除以墙钟秒计算，不能与全机多核百分比混用。

以下资源数值先用于 4 GB 参考档的候选预算。2 GB 或其他资源档位需独立建立基线与预算，不能直接套用后标记已支持。

| 指标 | 首轮目标 | 测量定义 |
| --- | --- | --- |
| 控制界面响应 | 本地反馈 P95 ≤ 200 ms | 从暂停/停止触发到手机本地显示对应状态；不等待远端模型确认 |
| 停止后的新动作 | 0 次 | 停止信号生效后不再提交新的设备动作；单独记录此前已提交动作的完成时间 |
| Agent 主线程任务片段 | P95 ≤ 4 ms、P99 ≤ 8 ms，无连续重任务 | 衡量自身回调、状态刷新与有界读写；同时测完整帧耗时，不能把片段预算当作整帧预算 |
| 空闲 CPU 增量 | 平均 ≤ 1% 单个逻辑核心 | 比较 B−A（状态定义见下一节）；同机同前台应用，除 Agent 状态外其他条件相同的配对窗口，排除初次启动和安装过程 |
| 空闲 PSS 增量 | ≤ 60 MiB | 开启但无任务相对关闭 Agent 的增量；统计涉及的全部 Agent 进程 |
| 活跃任务 PSS 增量 | 稳态 ≤ 180 MiB，瞬时峰值 ≤ 240 MiB | 比较 C−A，A 中手动执行等价的目标应用流程；包含网络、JSON、位图和新增进程开销；以低资源样本校准 |
| 常用应用启动回归 | 对中位数和 P95 分别要求增量 ≤ `min(100 ms, max(30 ms, 基线值 × 10%))` | 主指标为首帧显示时间 TTID，冷启动、热启动分开比较；30 ms 是短启动场景的初始容差，100 ms 是绝对增量上限；内容完全就绪时间能可靠测量时单列 |
| 应用卡顿增量 | 关键路径慢帧占比增加 ≤ 1 个百分点 | 按设备实际刷新率测量；120 Hz 和 60 Hz 使用对应帧期限 |
| 稳定性 | 必测任务中 Agent 引起的 ANR、崩溃、内存溢出为 0 | 同时观察被操作应用及系统服务；错误重试不能掩盖异常 |

CPU、内存和启动预算通过多个配对批次测量，不用单次最优样本验收。启动 P95 对每个所报告场景保留至少 100 次原始样本，样本不足时先报告中位数并标记 P95 待验证；P99 等更高分位同样需要足够样本与不确定性说明。若噪声足以改变结论，增加样本，不能直接宣称通过。

电耗、温升和 GPU 占用单独测量，不用 CPU 指标替代。首次参考机测试建立同温度、亮度、网络、供电与电量区间的基线，冻结可接受增量后纳入发布门槛；当前没有足够依据给出固定续航或温升保证。

按平台能力选择测量工具。`frameOverrunMs` 只适用于 API 31 及以上，Android 11 使用可用的帧时间、FrameMetrics 或系统 trace 并注明口径；缺少某个工具不等于指标通过。硬件功耗计不可用时采用有明确精度的替代测量，不能用短时间电量百分比跳动证明省电。

## 6. 基线与实验方法

### 三种 Agent 状态

| 状态 | 用途 |
| --- | --- |
| A：Agent 关闭 | 同一系统、应用版本、前台场景下的日常运行基线 |
| B：服务开启但无任务 | 检查是否存在持续截图、事件风暴、后台唤醒或不必要常驻开销 |
| C：Agent 执行标准任务 | 测量观察、模型等待、操作和结果验证的分阶段开销 |

使用同机配对，固定应用版本、缓存条件、刷新率、显示设置、温度和 Wi-Fi 条件；确认各组均未插实体 SIM、未启用 eSIM，并记录无线配置，不能只在其中一组关闭蜂窝无线电。交替测试顺序减少缓存和热降频偏差。三种状态分别记录自身资源开销及目标应用的体验，包含相关进程合计的绝对 PSS 与峰值，不能只报告差值或只测 Agent 对话页。

### 系统镜像对照

同一参考机还需对比原厂系统与目标系统；在许可和硬件条件允许时增加同基线、未集成 Agent 的 AOSP 镜像对照。记录两边系统、驱动、应用和服务组件差异，不把因版本或驱动变化造成的差异全部归因于 Agent。

原厂对照用于评价最终手机体验；同系统三态用于定位 Agent 的增量成本，两组结果分别报告。

### 远端模型耗时

端到端用时拆分为：观察、上下文构建、网络连接/上传、模型响应、工具校验、等待用户、设备动作和结果验证。对不支持流式接口的模型记录完整响应时间，不虚构首 token 时间。

本地性能基准使用固定响应与时延的测试模型服务，真实模型与实际网络另做端到端测试。远端耗时不计入本地主线程指标，但仍计入用户实际等待并在界面显示所处阶段。

## 7. 必测压力场景

- 2—4 GB 低资源样本、主流设备及不同显示刷新率；设备条件未满足时标记能力限制。
- 连续重复任务至少 30 分钟，每个任务仍遵守各自预算；反复开始与停止、反复开启和关闭服务，观察内存回落、对象泄漏、CPU 和温度趋势。
- 复杂长列表、频繁内容更新、动画、键盘弹出和旋转，不出现无界队列或整页重复编码。
- 断网、慢模型、超大/非法模型响应、用户迟迟不确认时，控制条仍可停止，资源有明确上限。
- 正常应用视频播放、音频播放、输入与后台通知同时存在时，Agent 闲置不引入可感知干扰；冻结应用流程包含 Wi-Fi 网络语音时另测其资源影响，不要求 Agent 自动处理来电。
- 进程回收、内存压力、系统热限制或省电模式触发时，优先减少 Agent 可选工作；不强制拉活或循环崩溃重启。
