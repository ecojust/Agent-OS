# Agent OS 功能规划

## 1. 产品目标

用户在手机内配置模型服务，用自然语言提出任务。Agent 理解目标、观察手机界面、调用应用能力或执行界面操作，并根据实际反馈继续处理。用户能看到执行过程，并随时暂停、拒绝操作或停止。

规划采用“先验证执行器，再集成定制系统”的路线。首版是可安装的 Android 原型；最终系统基于 AOSP，具备自己的对话入口、任务服务与执行层。两者复用任务协议及核心逻辑，通过不同的设备适配器连接平台能力。

### 已确定的产品决策

| 项目 | 决策 |
| --- | --- |
| 首版交互 | 手机内配置模型，直接对话操作 |
| 默认设备环境 | 无实体 SIM、无启用 eSIM，通过 Wi-Fi 使用；蜂窝业务与专门来电中断流程不列入首版范围 |
| 执行条件 | 手机亮屏且已解锁，操作过程前台可见 |
| 模型位置 | 默认使用用户配置的模型服务；本机负责调度与执行 |
| 系统基础 | AOSP；首个系统镜像目标为 ARM64 |
| 原型范围 | Android 11 及以上，逐步验证不同系统版本 |
| 兼容优先级 | 尽量覆盖近五年发布的手机；APK 保留原系统，ROM 按机型适配，不预先锁定所有设备使用同一 Android 版本 |
| 应用日常使用 | 保留标准 Android 应用底座；常用应用安装、升级和核心流程单独验收，不与 Agent 操作能力混同 |
| 性能原则 | Agent 按需运行、执行有界、停止独立响应；普通应用运行不经过模型代理，性能回归纳入发布门槛 |
| 用户控制 | 应用范围授权、逐步确认、独立暂停和停止入口 |
| 当前交付 | Android 执行器原型、功能规划和架构图；当前实现范围见 [IMPLEMENTATION.md](../IMPLEMENTATION.md) |

用户接管、授权有效期、工具契约、网络预算、数据、资料隔离、交互、更新及维护规则见[统一设计规则](DESIGN_RULES.md)。这些规则包含后续系统阶段目标，不能将规划清单视为全部已实现或已通过验收。

### 首版不承诺的能力

- 锁屏或无人值守执行、自动解锁、自动输入密码及处理生物识别。
- 操作所有应用、读取受保护页面，或绕过应用和系统权限。
- 直接刷入所有 ARM 手机；32 位设备与具体厂商适配另行评估。
- 在手机上运行任意大模型；本地推理属于后续扩展方向。
- 外部 Agent 接入、远程 MCP 控制、多设备协作；首版以手机内对话为入口。
- 蜂窝通话、短信、移动数据，以及专门的来电中断、接听与恢复流程；首版不为这些能力申请权限。

无卡不改变 Android 标准组件行为。锁屏、用户接管、撤权、遮挡和目标变化继续触发通用执行检查，不增加专门的电话、通知或闹钟处理子系统。

## 2. 首版使用流程

1. 配置模型服务地址、密钥、模型名称，测试网络及工具调用能力。
2. 了解界面信息会发送到所配置服务，并手动启用执行所需的系统能力。
3. 选择允许操作的应用；默认开启逐步确认。
4. 输入目标并启动任务。屏幕出现任务状态与暂停、停止入口。
5. Agent 观察界面、计划动作、请求必要确认、执行并再次观察。
6. 完成或中断时给出实际步骤、验证依据和未完成部分，用户可回到目标应用核对。

关闭逐步确认意味着普通操作可以在授权范围内连续执行。截图外发和系统确定的高影响动作仍需确认；无法可靠判断后果的动作不得仅凭模型自评自动放行。原型阶段不将付款、账户删除等高影响流程列为受支持任务。

## 3. 功能模块

### 3.1 对话与任务控制

- 任务输入、当前步骤、等待原因、执行结果及错误原因。
- 运行中的可见控制条，不依赖模型响应即可暂停或停止。
- 暂停阻止后续动作；已交给系统的动作可能正在完成，界面应如实说明。
- 停止取消模型请求和等待中的动作，清理任务资源；已经完成的外部操作不自动撤销。
- 锁屏、熄屏、执行服务失效时停止任务；重新解锁后由用户主动重新开始。
- 暂停、接管或确认超时使当前执行代次和旧确认失效；继续时重新观察。无法确认的前台变化暂停处理，不承诺 APK 可以检测每一次用户触摸。

### 3.2 模型配置与调用

- 支持服务地址、API Key、模型名称；区分配置保存、连接成功和工具调用可用。
- 首版使用兼容 Chat Completions 的工具调用协议，后续通过适配器扩展其他协议。
- 处理连接超时、认证失败、限流、不支持工具、错误 JSON 和上下文过长等情况。
- 多模态截图能力单独检测；仅支持文本工具调用的模型也可使用界面结构完成任务。
- 密钥使用系统密钥库保护，不写入普通日志、版本库或截图。
- 对配置了明文 HTTP 的局域网模型明确提示传输边界；公网服务使用 HTTPS。

### 3.3 应用发现与能力调用

- 只向模型提供用户授权的应用列表。
- 优先使用应用公开的接口、Intent 或 Deep Link；调用目标和参数仍需校验。
- 没有可用接口时，通过界面结构和受控手势完成操作。
- 应用启动失败、不可见或跳转到未授权应用时报告实际状态，不扩大授权范围。

### 3.4 界面观察与操作

- 读取当前应用标识、可见节点、文字、可操作状态与边界。
- 每次观察生成界面版本号，节点标识只在对应版本内使用。
- 支持节点点击、文本填写、滚动、返回、回到桌面与有限坐标手势。
- 操作前再次检查设备状态、应用范围和界面版本；坐标手势也不能绕过这些检查。
- 截图是按需能力，需明确确认；受保护窗口、密码页面和范围外画面不截图外发。
- 节点不完整或应用自绘时说明能力限制；不能将不可观察的操作报告为验证成功。

### 3.5 结果验证与失败恢复

- 区分“请求已发出”“系统接受动作”“观察到界面变化”“目标得到验证”。
- 连续动作之间重新观察，避免页面变化后仍使用旧节点或坐标。
- 对有副作用且结果不确定的操作，先观察或请用户接管，不盲目重试。
- 设置步骤数、执行时间、重复动作和网络请求预算，防止无限循环。
- 中断结果包括原因、最后确认的状态以及仍需用户完成的部分。

### 3.6 隐私与运行边界

- 模型可见范围与实际操作范围一致；未授权应用只返回必要的应用标识。
- 界面文字、应用内容和模型输出都需要按数据处理，不能替代用户授权。
- 截图和对话默认不落盘；任务日志尽量只记录动作类别、时间、状态与错误码。
- 如用户需要导出诊断记录，提供明确的预览与脱敏，不默认包含密钥、输入内容和图片。
- 进程重启后不自动恢复操作，防止过期任务继续执行。

### 3.7 系统级集成

- 系统桌面或系统入口可呼出对话和任务控制台。
- 将确需系统能力的执行接口接入受控的特权服务；模型、网络和任务计算不进入系统关键线程。
- 通过 Binder/AIDL 等明确接口暴露经过授权的能力；普通应用不能任意调用特权执行器。
- 系统权限按具体能力最小化分配，不能把“系统应用”视为无限制操作授权。
- 系统设置、包管理、网络等新增工具需独立设计权限、结果验证与测试。

### 3.8 兼容性与分级能力

- 首次运行和任务启动前检查系统版本、授权与执行能力，明确哪些工具可用。
- 核心流程以 Android 11 可用公共 API 为基线，新版能力通过隔离的平台实现按需启用。
- 优先保留无图像的结构化执行路径；截图或模型视觉能力不可用时，继续支持有有效观察依据的任务。
- 不支持的功能给出原因，不能通过权限绕过、伪造成功或降低安全要求实现兼容。
- 默认使用远端模型、有界上下文和串行任务，照顾低资源设备。
- 维护设备与系统构建号对应的实测结果，分别展示 APK、任务能力和系统镜像支持情况。

### 3.9 第三方应用日常可用

- 保留标准 ART、核心类库、Bionic/JNI、安装更新、权限、任务栈、WebView、图形和媒体组件的行为。
- 区分“能安装”“日常核心流程可用”和“Agent 可操作”，应用不能自动操作时仍应正常供用户手动使用。
- 固定常用应用样本与关键必测名单，测试登录、通知、播放、相机、分享、文件打开、更新和数据保留等流程。
- 设备认证、商业服务、DRM 和厂商组件依赖单独登记并纳入完整结果，不能以修改应用或伪造认证换取通过。
- 系统镜像执行适用的平台兼容测试后，仍需完成真实应用测试；详见[第三方应用兼容性与验收](APP_COMPATIBILITY.md)。

### 3.10 性能与运行开销

- Agent 不进入第三方应用启动、输入、绘制和媒体播放的同步关键路径，模型不可用不影响普通应用运行。
- 模型请求、图片编码和上下文处理使用工作线程；主线程读写有界，设备操作串行执行。
- 空闲时不持续截图、遍历界面或请求模型；任务运行时合并事件、限制队列和图片工作集，过期数据及时释放。
- 停止、锁屏和撤权优先于普通任务，恢复时重新观察，不能通过复用旧坐标提高速度。
- 建立启动、帧时间、CPU、PSS、稳定性及能耗预算；区分目标和测量结果，具体见[性能架构与验收预算](PERFORMANCE.md)。

## 4. 建议工具范围

以下为规划接口，采用[设计规则 R4](DESIGN_RULES.md#r4-工具协议与执行一致性)规定的内部协议版本、执行代次、资料身份和结果语义；[版本 1 schema](../core/src/main/resources/protocol-v1.schema.json)已实现。当前 Android 适配器仅开放结构化路径，`take_screenshot`、`tap`、`swipe` 不对模型提供，详见[实现范围](../IMPLEMENTATION.md)。

| 工具 | 作用 | 关键约束 |
| --- | --- | --- |
| `list_apps` | 列出可操作应用 | 只返回授权范围 |
| `launch_app` | 打开应用 | 包名必须获授权，返回后观察验证 |
| `observe` | 读取前台状态和节点 | 返回界面版本，敏感字段不返回值 |
| `resolve_node_at` | 按屏幕坐标与指定动作查找唯一节点候选 | 只读、绑定最近观察版本；不取代后续确认与最终校验 |
| `click` / `type_text` | 节点点击、填写 | 节点与当前版本匹配 |
| `scroll` | 滚动页面或容器 | 只操作授权应用的可滚动区域 |
| `tap` / `swipe` | 坐标点击与滑动 | 校验屏幕边界、遮挡与界面版本 |
| `back` / `home` | 系统导航 | 不自动扩大后续应用权限 |
| `wait` | 等待页面变化 | 有明确时限，可取消 |
| `take_screenshot` | 为多模态模型提供画面 | 用户确认、范围校验、受保护画面拒绝 |

工具只接受结构化参数，不提供任意 shell、任意脚本或直接文件系统执行通道。

## 5. 里程碑与验收

| 阶段 | 交付物 | 通过条件 |
| --- | --- | --- |
| M0：设计基线 | 功能规划、架构图、统一设计规则、状态与执行流程 | 无卡 Wi-Fi 范围、接口边界、限制和后续决策清楚 |
| M1：可安装原型 | Android APK、模型配置、任务控制、设备工具与 schema | 连接真实模型完成无卡 Wi-Fi 受控示例；R1—R8 的核心契约落地，授权、取消、锁屏停止有效 |
| M2：可靠执行 | 应用能力适配、错误恢复、诊断、兼容性矩阵和自动化测试 | 多轮任务有观察依据；失效节点不执行；异常场景无遗留动作；不同版本及厂商样本的结果与限制可查；Agent 三状态性能与应用回归达标 |
| M3：参考机型系统 | AOSP 集成、设备配置、可恢复刷机方案 | 真机启动与关键硬件通过；系统入口与权限隔离有效；平台兼容测试、固定应用样本及系统性能通过验收 |
| M4：扩大覆盖 | 经过验证的设备列表、可选 GSI 方案 | 每种镜像标注设备条件、已测功能、已知问题和恢复方式 |

不以“编译成功”替代功能验收，不以模拟器通过替代具体手机的硬件验证。

首次正式 APK 发布还需满足设计规则 R9 的签名与配置迁移要求，以及 R10 的构建和验证证据；正式 ROM 另需每机型更新恢复与维护记录。

### 首批端到端测试任务

- 打开授权的系统设置页面并核对当前状态，不修改无关设置。
- 在专用测试应用内填写文字、滚动、点击，并读取实际结果。
- 在两个授权测试应用间切换，完成步骤后验证前台应用与目标状态。
- 人工在中途切换页面，确认旧节点操作被拒绝。
- 在模型请求、等待确认和执行间隙分别停止任务，确认后续动作不再执行。
- 熄屏、取消授权、断网、模型返回非法工具时安全结束并给出原因。
- 密码字段、未授权窗口、受保护截图不进入模型上下文。
- 确认超时、重复调用和写操作结果未知不会导致自动重放；Wi-Fi 断开、窗口遮挡、配置迁移失败和密钥失效返回真实原因。

## 6. 设备与兼容路线

原型以 Android API 兼容为基础，不绑定特定 ARM 芯片。系统镜像首版聚焦 ARM64，32 位 ARM 独立评估。

兼容性优先，目标尽量覆盖近五年发布的手机。当前规划窗口为 2021-10-26 至 2026-10-26；APK 仍需当前系统达到 Android 11/API 30。应用核心优先不依赖原生 `.so`，实际 32 位和 64 位 Android 的 APK 能力分别验证；ROM 的 ARM64 范围与 APK 范围分开。

详细的版本策略、能力降级、低资源策略和验证矩阵见[兼容性策略](COMPATIBILITY.md)。AOSP 基线保持待定，以目标设备的可靠适配和可维护性共同决定，不因扩大覆盖而宣称所有手机可以使用同一刷机包。

GSI 可以减少系统层重复适配，但前提包括 Bootloader 可解锁、完整支持 Treble、架构匹配及系统与厂商接口兼容。GSI 不是带有所有手机驱动的完整固件。

参考手机尚未确定。选型时考察可解锁性、原厂恢复镜像、驱动与设备资料、可维护的系统版本，以及相机、Wi-Fi、蓝牙和功耗测试条件；蜂窝业务不列入首版门槛。机型支持按具体设备与版本组合分为“已验证”“有限支持”“未验证”“不支持”，不使用未经实测的通用兼容承诺。

## 7. 后续需要确定

- 参考手机与 AOSP 基线版本。
- 首批验证的模型服务和第三方应用。
- 统一交互规则下的具体视觉方案、默认应用与分发方式。
- 首个正式支持机型的维护日期、补丁来源与经过验证的更新恢复方式。
- 是否增加语音入口、本地推理、外部 MCP 和多设备能力。
