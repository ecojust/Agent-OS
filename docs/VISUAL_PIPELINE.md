# 受控视觉观察与坐标操作

本文区分已经实现的内部模块、现有测试证据和开放生产能力前仍需满足的条件。**普通 debug/release 安装包未开放 `take_screenshot`、`tap`、`swipe`，服务也未申请截图和手势能力。** 专用 `visualAcceptance` 构建仅为 API 34+ 原生截图链路验收申请截图能力，不是用户功能发布。核心层的图片附件处理不代表模型图像能力或真机视觉任务已验证。

授权、确认与执行代次遵守 [DESIGN_RULES.md](DESIGN_RULES.md)，资源上限遵守 [PERFORMANCE.md](PERFORMANCE.md)。已实现核心附件、受限的只读节点定位、内部窗口捕获与转换、可信图片审阅及其交接模块；已加入类型化工具入口和固定页面策略的内部接线，但主界面未提供启用开关，普通包服务不申请截图或手势权限。真实原生截图到模型的正向验收尚未完成。

## 2. 核心附件模块

该模块已有合成图片及真实回环 HTTP 回归，无须启用 Android 截图权限；这类证据不等于生产设备截图已可使用。

- 只有当前可用工具清单中的本机 `take_screenshot` 成功结果可以产生图片附件。模型返回的文字、其他工具结果或 URL 不能自行建立附件。
- 附件绑定原请求的 `taskId`、`profileId`、执行代次、`callId` 和 `expectedRevision`；结果中的 `data.revision` 必须匹配。不得在暂停恢复后为旧图片绑定新代次。
- 每次只保留一张待发送图片。图片不进入工具调用去重记录、普通工具文本、任务日志或长期对话历史；重复 `callId` 不再次附图。
- 附件仅供下一次模型请求消费，之后释放。观察刷新、界面写操作、暂停、停止、任务结束或配置变化使待发送图片失效；同轮后续操作也必须执行该规则。
- 首轮仅接受受限的单帧 PNG；JPEG 等格式待有界校验路径单独验收后再开放。检查实际内容与声明尺寸一致：编码数据至多 1 MiB、长边至多 1280 像素、总像素至多 1,048,576。限制检查先于大额解码分配；不以扩展名或 MIME 前缀证明格式正确。
- 网络失败不自动重发图片。清理本机引用不等于删除模型服务收到的数据；正在退出的网络请求可能短暂保留发送缓冲，不能宣称停止后立即物理擦除所有副本。

`ToolHandler.execute(ToolRequest, RunControl)` 已支持 `LocalToolResult` 直接交接唯一 `PngImage`，保留完整原请求，不生成 dataURL 或再次复制 PNG。Dispatcher 校验工具、原版本与实际尺寸后，将图片从去重记录和普通文本中分离；Runner 仅在下一次模型请求消费它。旧 `imageDataUrl` 返回值保留为兼容输入，仍须有界解码与校验，不能与直接 PNG 混用。HTTP 路径从 PNG 分块编码，不创建完整 Base64/dataURL 字符串。`windowId`、窗口边界和 `captureId` 等元数据本身不授予截图、披露或坐标操作权限；Android 内部交接和条件化 Controller 路由已经实现，普通安装包仍不启用设备截图能力。

## 2.1 已实现的受限节点定位核心

`CoordinateNodeResolver` 是独立的只读候选解析模块，不生成触摸手势。输入坐标使用与 `observe.bounds` 一致的屏幕坐标像素，不接受 dp、归一化或缩放截图坐标，也不将其称作硬件面板像素。

请求绑定任务、资料、执行代次、包名、默认显示器、窗口、界面版本和窗口边界。完整且有界的观察中，只返回支持所请求节点动作的唯一候选；同动作歧义、截断、旧版本、敏感和未知遮挡均拒绝。模块不持有平台节点或页面文本，不授予任何执行权限；候选后续仍须走原有确认和最终设备校验。

滚动是既有节点动作，不是触摸路径：查询点必须在安全区域且不落在可信控制条上，容器完整位于窗口内并与安全内容相交；点击和文本候选还须完整位于安全内容中并避开控制条。所有动作均拒绝与未知遮挡或危险节点相交的候选。首批 17 项纯 JVM 测试通过；Android 已接入独立的只读定位工具；第十七轮的后续点击失效记录保留；第十八轮完整八档回归通过，正向用例仅在明确未派发后重新观察、重新解析并独立确认。不能据此宣称截图或坐标手势已经开放。

## 2.2 Android 只读节点定位工具

`resolve_node_at` 只接受最近一次成功 `observe` 的版本与屏幕坐标；`coordinateSpace` 必须显式为 `screen_pixels`，`action` 为 `click`、`type_text`、`scroll_forward` 或 `scroll_backward`。它不换算图片坐标，不点击、不输入、不滚动。示例参数：

```json
{
  "x": 120,
  "y": 280,
  "coordinateSpace": "screen_pixels",
  "action": "click",
  "expectedRevision": "从最近observe获取的版本"
}
```

结果包含节点编号、动作、边界、窗口及原版本，明确标记 `candidateOnly`、`requiresConfirmation` 和未提交。取得候选后，模型仍需发起既有节点工具调用，由原有确认和最后检查决定能否执行。候选不更新规划器的观察版本；同一模型计划已经写入或取得图像时，继续定位会被拒绝并要求重新规划。

平台适配器在同一工作线程使用新快照，核对授权、平台实际支持的动作、控制条凭据、窗口和原执行代次。当前仅默认显示器可用，已知敏感页面、未知窗口遮挡与不完整观察拒绝。实际支持的点击、文本设置及滚动方向参与观察版本，能力变化也使旧计划失效。

## 2.3 图片审阅会话核心

`PngImage` 持有经过有界校验的最终 PNG，不接受后续内容修改；预览与消费来自同一份编码。共享校验器检查文件结构、校验和与实际解压行数，编码上限仍为 1 MiB、长边 1280 像素、总像素 1,048,576。校验直接从原 PNG 的每个 IDAT 片段向解压器供给数据，保留一个固定 8 KiB 输出缓冲，不再聚合压缩数据或复制整份 IDAT。成功和异常出口清理输出缓冲并关闭解压器；先分配 Java 缓冲再创建解压器，避免缓冲分配失败遗留无所属对象的 native 实例。调用者和渲染器的副本仍需各自释放，这不等于整个流程满足 24 MiB 实际峰值。

`ImageReviewSession` 只管理一次本地审阅，既不捕获设备，也不发送网络请求。它绑定任务、资料、原执行代次、调用、捕获、安装身份、窗口几何、观察版本，以及不含密钥的模型接收方和配置标识。可信宿主取得一次带生命周期的只读预览流并实际呈现后，才能取得独立图片许可；该许可不接受文字确认，也只能消费一次原 PNG。

60 秒有效期从创建开始计算，准备图片和确认不会重新计时。拒绝、超时、宿主失效、暂停、停止、配置或绑定变化使未消费图片失效；旧宿主回调及其他会话的许可不能操作新会话。会话不覆盖模型请求的取消钩子，宿主负责独立调度到期清理，控制器须在状态变化时及时通知。

新增 16 项 JVM 测试通过，该模块提交时完整核心测试为 129/129；原图片附件测试仍通过。网络发送守卫已有独立回归，但不能代替设备捕获、审阅和生产 Controller 的完整披露验收；工具和平台权限保持未开放。核心有界校验不等于整个捕获与渲染流程已经满足 24 MiB 图像工作集预算。

后续流式校验优化新增 12 项 JVM 回归，覆盖 IDAT 任意分界、空块、跨块尾随数据、拼接压缩流、截断、行过滤和解压量限制；该优化完成时完整核心测试 180/180 实跑通过。Android 主程序、仪器测试编译及 lint 通过，并已包含在第二十八轮八档完整通过的模拟器矩阵中。优化减少的是确定的压缩副本，不是设备内存测量结果。

## 2.3.1 已知图片缓冲容量与读取者生命周期

`ImageWorkset.process()` 为进程内已知、由应用持有的图片缓冲容量提供共享 24 MiB 准入。PNG 工厂在复制调用者输入前预约编码容量和固定校验缓冲；验证成功只保留编码预约，失败或 Error 出口归还未移交资源。模型请求的最终 UTF-8 正文也使用同一池；调用者源数组、既有 Base64/dataURL 字符串、JSON 对象、编码器／HTTP 内部缓冲、GC、平台解码器及 GPU 不包含在计数中，不能将它称为全流程物理内存上限。

`PngImage.openRead()` 返回不暴露内部数组的 `ReadLease`，支持在同一份只读编码上读取、定位和重读。关闭 PNG 所有者立即阻止新读取者；已经开始的读取者可以完成解码，直到最后一个流关闭才擦除编码并归还其预约。读取者关闭幂等，转交已确认的 PNG 不复制、不重复计费；消费者自己的输出缓冲需自行管理。审阅会话只签发一次 `openPreviewRead`，仍校验宿主、原代次、绑定、配置与时限。构造异常也会结束已经开始的审批等待，避免活动计时停留在等待状态。

新增 19 项核心回归覆盖共享准入、溢出、重复关闭、复制前拒绝、分配与验证异常、原数据隔离、在途读取、mark/reset、关闭和一次许可移交；该模块完成时完整核心测试 **199/199 实跑通过**。这验证资源所有权协议，不代表设备内存峰值验收。

模型网关随后增加独立请求正文所有权：保留私有 JSON 快照，在工作线程两遍编码，第一遍有界计算实际 UTF-8 长度，第二遍在预约后直接写入精确数组，核对两遍长度和摘要。最多 4 MiB，沿用原 JSON 转义和 Unicode 行为，不生成完整的中间 JSON 字符串。正文移交给具有 `PENDING / RUNNING / RELEASED` 状态的网络任务；排队但未运行的任务由调用工作线程撤销，在途任务只由原网络工作线程退出时擦除并归还。Future 已取消、调用者已返回或连接正在断开，都不代表可以提前释放正文。同步取消钩子只取消、移除排队任务并安排断连，不擦除大缓冲。

任务图片发送已进一步改为强类型分块编码。`ImageAttachment` 持有已验证的 `PngImage`，按原任务、资料、代次及观察版本只转交一次；Runner 在准备消息与工具定义后交给 HTTP 请求，请求从最外层异常出口负责关闭 PNG。编码结束便释放原图，进入网络队列的只有最终正文；取消请求仍须等在途网络线程退出后擦除正文。

本地旧 dataURL 入口按字符读取 ASCII，经标准 Base64 解码流写入预约后的临时数组，不创建完整 substring 或额外的完整 ASCII 数组；保持缺省补位兼容，拒绝补位后尾随字符。临时解码数组、不可变 PNG 副本和校验暂存同时计入准入；临时数组擦除后才归还额度。原始 JSON 字符串仍由调用者持有，不声称能够擦除它。

`ImageRequestSerializer` 仅写入本方固定的图片消息结构，普通 JSON 字段继续使用原有 Gson 设置；不通过查找或替换文本占位符插图。一个只读流跨两遍复位，3 KiB输入及4 Ki字符输出共11 KiB固定暂存在分配前预约，编码块之间检查配置和任务。最终正文仍受4 MiB限制及两遍长度、摘要一致性校验，图片不进入对话历史或重放记录。

新增10项 JVM 回归覆盖所有补位长度、跨块数据、原 JSON 字节兼容、精确大小边界、预算不足、编码中取消、异常清理和真实 HTTP 在途所有权；完整核心 **223/223 实跑通过**。另新增1项 Android 回归使用公开 Runner、合成 PNG 和四轮真实回环 HTTP，由平台解码器独立核对像素、UTF-8以及后续历史不含图片；测试 APK 编译与 lint 通过，第三十三轮新增8次执行全部通过，该轮完整矩阵1024项全过。此优化仅针对任务附件路径，独立 `VisionModelProbe` 的合成图仍使用既有 dataURL；JSON 对象、编解码器及 HTTP 内部副本、GC和GPU不包含在容量计数中。

## 2.4 原生图片审阅组件

`ImageReviewView` 显示目标应用包名、完整模型接收方和同一最终 PNG 的预览，支持通过矩阵缩放和平移查看图片。确认按钮仅在图片解码、挂载和可见布局完成后启用。工作线程负责解码；主线程只挂载不可变位图，不重新截图或编码。已交给渲染器的位图先断开 Drawable 引用，不在后台强制回收仍可能绘制的位图。

内部 `SecureImageReviewDialog` 要求宿主窗口和自身窗口均保留 `FLAG_SECURE`。进程同时只接纳一个审阅宿主和一个解码/待挂载结果；过期、失焦、销毁、配置变化或内存压力会撤销尚未消费的许可。拒绝新宿主时清理新会话，重复的未显示窗口不能撤销实际宿主；迟到解码结果丢弃并释放。非主线程关闭先同步使已持有的许可失效，再安排界面清理。

预览解码前从同一共享池预约 4 MiB 已知像素容量和 16 KiB 显式 `inTempStorage`，直接消费只读 PNG 流；临时缓冲在解码返回后擦除并归还。输出继续核对尺寸、ARGB_8888、不可变性及 `getAllocationByteCount()`，超过预约则拒绝，不把事后回收写作没有超限。`DecodedPreview` 将像素预约从工作线程移交到主线程和 View；迟到且未展示的结果可以回收，已经交给 View 的图像先解除引用，只归还本方所有权额度，不能由此证明 RenderThread 或 GPU 已释放。单工作线程、单预览准入和容量为一的交接队列限制并发，原线程仍在退出尾部时也不会错误拒绝下一次已准入工作。

新增五项真实 Android 仪器测试检查预算不足时不调用解码器、失效后的在途读取、待主线程消费结果的额度、已展示 Bitmap 不强制回收，以及解码异常后的下一次预览。主程序、测试 APK 和 lint 通过；第二十八轮八档新增 40 次执行全部通过，该轮图片审阅合计 112 次通过，保护窗口的采集保持 blocked。

把应用 Activity 切到前台会改变原任务焦点，所以内部 Dialog 不能复用切换前的目标授权。服务审阅路径已改用下面的非焦点浮层和实际窗口守卫，仍无生产 Controller 入口。保护窗口的截图采集保持 blocked，不临时清除安全标志来生成界面证据。

### 共享宿主准入与预览解码

`ImageReviewPresentationCoordinator` 和 `ImagePreviewLoader` 分别管理宿主准入与解码工作，安全 Dialog 和服务浮层共用同一实现。进程同时只允许一个审阅宿主；原 token 撤销、已展示图片引用解除且实际窗口移除完成后，才释放宿主准入。旧对象的迟到释放不能清除替代宿主。

解码/待主线程消费的结果独立占据单一槽，宿主关闭不会提前释放该槽。读取者、像素和暂存预约沿用原有真实生命周期，工作线程返回不等于主线程已经接收/丢弃结果。宿主claim后发布记录分配失败时，只撤销本次原token，避免会话与PNG无所属对象。

3项共享准入协议测试使用实际 BitmapFactory 和受控屏障；其内部协议宿主不作为真实窗口证据。Dialog 与服务浮层互斥的真实窗口测试另行验证，均已纳入第四十二轮八档通过的基线。

### 内部服务图片审阅浮层

`SecureImageReviewOverlay` 由执行服务独立创建、持有和销毁，使用安全且不抢输入焦点的无障碍浮层，放在紧凑任务控制条下方；空间不足时拒绝显示。实际View的窗口token、ID、显示器、附着代次和几何形成独立身份，不能按标题或包名寻找替代窗口，也不能借用任务控制条身份。该宿主尚无生产Controller、截图工具或网络入口。

主线程只发布轻量身份、挂载预览和处理控制；有界工作线程首次解密核对真实保存配置的接收方与应用授权，随后保留无密钥身份信息。窗口核验共用进程设备门和既有公开缓存刷新路径，检查原任务/代次/配置、实际安装身份、目标唯一焦点、两个本方窗口的实际边界和未知遮挡，包括仅遮住暂停/停止控制条的情况。首次平台窗口登记受固定初始期限约束，只有当前结果被主线程采用后才完成首次核验；被淘汰的后台结果不会解除期限。此检查只证明宿主与窗口元数据，不能替代目标节点版本、隐藏敏感内容或最终图片披露守卫。

浮层使用共享单宿主与单解码/待挂载准入，实际图片呈现且窗口身份核验后才允许批准，不依赖非焦点窗口不可能取得的输入焦点。暂停、配置变更、服务失效、目标内容/滚动/选区变化和已观察到的外部窗口变化撤销旧图片。已经批准但尚未消费时，外部窗口变化同步撤销许可，不等待异步重验；真实附着/几何变化也撤销，批准文案引起的普通布局不重新签发或误撤销。身份等待的同步future回调只在上述校验之后完成。

关闭先撤销本会话、解除图片引用，再移除实际窗口。`whenRemoved()` 仅在实际 View 脱离、预览引用清除、服务登记和共享宿主占用解除后完成；每个等待者相互独立，取消或手动完成一个等待者不能伪造其他等待者的移除确认。移除失败时保留原宿主占用，直到实际清理成功。确认不代表在途解码、RenderThread 或 GPU 已释放；读取者仍由原工作完成后结算。普通设备写操作仍将该独立浮层视为遮挡，没有新增豁免。

第四十二轮包含10项真实浮层回归，在 API30–37 八档均通过：同图一次消费、实际配置/代次失效、解码清理、普通写阻断、Dialog 互斥及两项实际移除确认测试。外部窗口事件用例是确定性的事件处理回归，不宣称实际发生了系统焦点切换。低 API 可验证审阅宿主，但仍不能进行按窗口捕获。安全标记始终保持开启。

捕获转换仍受原固定5秒期限；本地审阅从会话创建起独立计60秒，不为原捕获许可续期。捕获收据、新鲜最终检查和内部审阅交接现已实现，详见第3节；生产 Controller 接线及受支持页面契约仍未完成。

## 2.5 独立合成图片能力探测

`VisionModelProbe` 只发送临时生成的 512×256 PNG：两行四列的八种颜色随机排列，带有清晰的中灰边距。提示和参数定义给出可用颜色名及一次随机 nonce，不包含正确排列；必须依据实际图片返回完整顺序。仅校验一次无副作用的探测工具回复，不执行任何模型要求的设备操作，也不读取任务、资料标识或应用内容。

网络响应、工具协议与合成图片校验分别报告，正确回复仅表示这一次合成图片测试通过。它不能证明任意真实界面的理解质量，不自动开放截图工具。沿用现有取消、时限及不重试策略，取消和旧代次继续作为中断处理；不转到其他模型服务。

新增 17 项真实本地 HTTP 测试，从实际请求中的 PNG 独立解码并构造答案，覆盖错误排列、旧 nonce、非法参数、错误响应、重定向、取消和超时。完整核心测试 146/146 实跑通过；真实模型服务尚未验收。

原生模型配置页已提供独立的“测试图像理解”入口。连接、工具、合成图像三项结果分别显示，同一配置的图像测试不会把工具测试自动标为通过；任一连接字段变化会取消旧请求并清除验证结果。一次点击仅发起所选择的探测，沿用取消按钮与本地 HTTP 信任确认；旧提示框不能授权后来修改的地址或配置。新增七项原生仪器测试，使用真实回环 HTTP 服务解码 PNG 像素并返回答案；主程序、测试编译及 lint 通过，七项用例已在第十九轮八档模拟器通过。受保护配置页面不临时解除安全标志采集截图。

新增的显式接口让同一探测算法绑定原执行代次和纯内存发送守卫，贯穿图片生成、既有HTTP检查点、解析和结果返回。5项新增回环HTTP核心回归通过，完整核心263项通过。守卫在I/O边界检查；没有配置监听器时，不保证正在阻塞的调用立即结束，已经发送的字节也不能撤回。

内部 `SavedVisionProbe` 从真实保存配置读取模型，并只在同一配置许可仍有效时发布进程内诊断。一个原子状态同时管理单次探测准入和旧记录撤销，旧请求的清理不能删除后来的记录。记录不保存密钥、图片或响应正文，绑定原探测代次和固定10分钟新鲜度；取消、配置替换、到期或时钟回退后失效，重新测试失败不沿用旧成功。它不是截图许可或通用图像能力认证，也不参与任务能力判断。8项真实存储/HTTP仪器测试在第四十五轮八档64/64通过；草稿界面中的临时测试结果不能签发这类记录。

已保存配置的原生诊断入口现已接入：同一按钮依据真实加载／保存的配置许可和未修改的界面状态区分保存模式与草稿模式，不自动保存用户修改。成功记录绑定原探测控制对象、执行代次及配置；网络完成后按钮恢复可用，但记录所有者独立保留。编辑、保存、离页、到期或另一真实探测替代该记录时撤销。仅在前台有记录时保留一个至多每秒的纯内存检查；有效时不重绘、不读存储，也不延长记录期限或原活动预算。工具测试不错误撤销图像记录，旧回调不能取消后来记录。7项新增真实界面、存储和PNG HTTP回归在第四十六轮八档56/56通过，APK与lint通过；没有长等10分钟的界面验收，期限边界已有内部记录测试。

## 2.6 按窗口捕获的测试进程桥

新增测试 APK 专用的 `CaptureBridgeService` 与受目标应用实际 UID 限制的 provider。桥只依赖 Android/JDK 类，独立进程加载，不依靠被测应用的静态字段或类加载器；测试客户端持有 provider 连接直到恢复设置并确认服务解绑。Android 平台为 instrumentation 包和 target 包建立双向可见性，产品清单无需增加测试查询或捕获权限。

桥通过自己的服务连接重新读取唯一焦点应用窗口，核对默认显示器、窗口 ID、边界和固定合成 fixture 包；调用者提供的 ID 仅用于比对，不能自行指定任意捕获对象。API34及以上只调用实际 `takeScreenshotOfWindow`，API30–33明确返回不可用且不改用整屏捕获。平台回调只交接或关闭缓冲，窗口复核在工作线程进行。

成功时通过 Binder 传递实际 `HardwareBuffer`；发送方在编组后关闭自己的句柄，接收方独立关闭另一份句柄。单项测试核对不同 UID/PID、原始窗口与缓冲元数据、四象限真实像素，以及两端关闭计数。低版本只验证不可用与零平台调用，不计为截图支持。失败结果只包含阶段和有界技术元数据，不携带图像；过期结果自行关闭，旧服务的清理不能取消替代服务的请求。

应用、测试和 fixture APK 构建及 lint 已通过，并检查了实际 APK 清单：捕获 service/provider 和 `canTakeScreenshot` 只存在于测试 APK，产品服务仍不具备截图或手势能力。第三十四轮八档测试均在回调入参解包时出现匿名子类加载错误，未执行到真实捕获或不可用断言；现将回调显式重建为平台 `ResultReceiver` 代理并核对两端类名，保留本地回调用于排空及迟到结果清理。修正后第三十五轮八档全部通过：API30–33不可用且零平台调用，API34–37真实按窗捕获、四象限像素及双方句柄关闭通过。像素证据来自测试对真实缓冲的独立检查，普通 fixture 截图只记录测试现场，不替代该断言。该桥只验证专用合成环境的可行性，不是生产授权、24 MiB实际峰值、敏感页面拒绝或真机性能的验收。

## 3. 开放设备截图前的最小条件

### 内部捕获接线与异步资源边界

已实现内部 `WindowCapturePermit`，复用 `AndroidDeviceTools` 的真实快照、配置许可、安装身份与自有控制窗口检查。私有构造的许可绑定原适配器、任务对象、执行代次、服务连接、观察版本、安装授权和控制条身份；测试用布尔配置守卫不能签发，模型参数不能构造。许可不含节点与页面正文，不是图片外发许可。`Snapshot` 已分别保存原始根边界、完整窗口边界及安全内容，首个路径要求根覆盖完整窗口，返回的几何均为值副本。

准备与同步提交分别取得设备门，提交阶段重新构建完整快照并匹配原许可；两阶段均在读取节点前核对亮屏解锁及个人资料，之后复查授权、完整性、敏感/高影响页面、未知遮挡和几何。固定5秒从准备入口开始，慢调用和重试不能延长。外国适配器/任务的调用不消费许可；原所有者一旦尝试提交，后续失效、超时或异常均不可复用，进入后端前才标记提交准入，门保持至后端实际返回。

共享检查取消任务时改用原代次原子取消，清理钩子在锁外执行，不取消已经恢复的代次。新增9项 Android 仪器测试使用真实保存配置、窗口和叠层，后端仅作提交计数，无原生截图；第三十六轮API35/36的敏感页用例在前置读取时失效；只读分类测试调整为最多三次新观察后，第三十七轮API34+的36次许可边界全部通过，低版本36次仅验证不支持。最终仍须命中对应拒绝，不改生产守卫。许可现已接入内部原始缓冲和转换模块，生产工具入口仍关闭。

为避免异步截图拖住应用操作，分开管理两种占用：

- **设备操作门**只覆盖同步的前置快照、平台捕获提交直到调用实际返回，以及结果到达后的独立后置快照。原调用仍未返回时，停止或超时不能伪造释放。
- **捕获槽**从请求准入保持到原始缓冲和本方图像工作实际结束。调用者取消不释放槽；迟到回调关闭自己的缓冲，旧回调不能释放新请求的槽。平台始终不回调时，只停用新的截图，不阻止已经可以重新取得设备门的结构化操作。

平台回调只取得、交接或关闭句柄；有效结果由原工作线程重新取得设备门后复核，过期结果直接关闭。不得把后置检查排入正在等待它的同一单线程队列，造成自我等待。提交返回与回调完成独立记录，覆盖回调先到和提交状态不确定的情况，不自动重发截图。

验证分别覆盖真实快照许可、异步所有权和格式转换；测试进程桥只提供平台行为证据，不能替代产品服务的权限与许可。原始缓冲的实际 stride、平台/GPU 开销仍不可由 Java 的宽高乘积证明，已知容量预算不等于物理内存峰值。

### 内部异步原始缓冲模块

`WindowBufferCapturer` 已实现独立进程级槽、单工作线程与容量为一的队列；空闲线程可退出。请求从启动起共用固定5秒期限及原任务/配置检查，不能因准备、回调或结果转交延长。`start` 返回生命周期句柄，`awaitAndClaim` 只允许工作线程一次转交；就绪通知不直接持有可被取消遗失的原生资源。默认后端绑定原服务，实际能力检查在设备门内完成，慢检查后再次复核原上下文才进入平台调用。当前产品服务没有截图权限，默认后端明确拒绝且释放槽。

同步提交、原生终态、工作线程退出、结果转交和缓冲实际关闭分别记录。回调先到不释放设备门；取消/超时结束调用者等待，未回调的请求继续占据截图槽，结构化工具在同步提交返回后仍可使用。提交结果不确定不自动重发。回调只交接或关闭句柄，原工作线程恢复后自己取得设备门执行完整后置快照，避免等待自身队列。

`OwnedWindowBuffer` 在关闭所有者后禁止新借阅，已有读取者退出前保留原句柄。原生关闭、实际关闭确认、预算归还与一次性通知均在锁外执行；未确认关闭则保留资源，可显式重试。相同Java句柄的重复通知不能关闭首个结果，独立句柄引用分别关闭；失败的额外句柄保持故障占用，不声称所有资源已归零。旧请求的结算不能清除新槽。

提交前按完整窗口的 `width × height × 8` 预约共享池中的保守逻辑容量；返回后检查单层RGBA8888/FP16、实际RGB色彩空间、尺寸、保护标记及提交到回调之间的时间戳，不把非sRGB标为sRGB。预算不足在原生调用前拒绝；捕获层保留原预约，后续转换器在有效读取者内重新核对RGBA布局后才可缩减。公开接口没有stride/分配字节数据，因此这不是24MiB物理/GPU峰值的证明。

新增14项捕获协议回归使用真实配置、原设备守卫和后置读取屏障，注入后端只创建合成 `HardwareBuffer`；另有4项真实合成缓冲的读者所有权回归。主程序、测试APK和lint通过；第三十八轮API34–37的56次捕获协议与全部八档32次缓冲所有权验证通过，API30–33另56次只验证不支持。这些捕获协议用例不覆盖Bitmap、PNG、预览或网络发送，不能把合成缓冲测试当作生产服务的端到端截图验收；测试专用平台捕获桥的证据仍独立保留。

### 内部窗口 PNG 转换

`WindowPngConverter` 消费已经通过前后许可检查的 `CapturedWindow`，只在工作线程执行，原任务、配置、服务、控制窗口身份及捕获/请求较早的固定5秒期限贯穿复制、缩小、编码和最终交付。它没有工具、界面或网络入口，不会延长捕获许可来等待用户。

首版仅转换实际单层RGBA8888、sRGB数据，P3及FP16明确拒绝，不改色彩标签冒充兼容。有效读取者重新核对真实布局后，将原始保守8字节/像素预约缩减为4字节/像素；同一工作集锁保证减少与关闭不会重复归还。缩减的是已知逻辑容量，不是stride、native分配或GPU占用测量。

全尺寸软件副本在分配前单独预约，硬件包装经显式复制后回收，原始读取者和句柄实际释放后才缩小。缩小使用软件Canvas，不隐式创建硬件缩放副本；长边至多1280像素、面积至多1,048,576像素，不上采样。软件图实际分配超过预约时拒绝并记录实际值，不能靠随后回收宣称没有超限。原始句柄关闭后，独立转换持有者仍保留原捕获槽，直到编码工作及清理结束。

编码使用预先预约的固定1 MiB数组，有界输出流超过容量即拒绝；只将有效PNG区间复制一次交给既有不可变校验器。每次编码写入及最终交付仍检查原任务；平台压缩吞掉流异常时恢复原暂停/停止原因。调用者取消不从另一线程回收正在复制或编码的图片。

每个转换预先建立一个有限资源记录。硬件包装、Canvas或软件图未确认解除引用/回收时，记录继续由原捕获槽持有，保留相关缓冲、读取者和预约；不会假报清理完成并开放新截图。成功PNG仅在清理及最终上下文检查完成后移交，任一失败关闭未移交PNG。

新增7项仪器测试使用真实保存配置、窗口许可、合成HardwareBuffer以及实际Bitmap/PNG编解码，覆盖像素/透明度、P3拒绝、复制前预算拒绝、实际超额分配、复制及编码中的取消、原始句柄关闭后的槽占用，以及大窗口缩小和真实PNG超限。唯一的大窗口用例保存并恢复实际显示尺寸覆盖值，不伪造许可几何；源图在固定捕获期限开始前准备。低API仅验证按窗口入口不支持，不能算作转换成功；这些合成测试也不替代原生截图、生产披露或物理内存验收。

### 捕获收据、审阅上下文与内部交接

`convertCaptured` 仅在原期限内完成转换后签发私有构造的 `CapturedPng` 收据，保留完整不可变 `ToolRequest`、原适配器/任务/配置身份、捕获几何和最终 PNG 摘要。PNG 只转交一次；转换或收据构造失败关闭未移交资源，外国请求不消费合法所有者的收据，未转交图片在收据关闭时释放。平台来源与合成后端/编码器来源不能互相提升；旧的无请求原始缓冲不能签发收据。收据记录过往捕获，不更新原5秒许可；稍后交给审阅仍须满足原任务和真实配置租约。

每张收据只建立一个 `CapturedReviewContext`，从同一真实保存配置读取接收方并核对应用安装授权，不保留密钥；存储读取不持收据锁，返回前再次核对原绑定。`currentBinding()` 只检查任务、配置和服务生命周期，不声称目标页面未变。转交后的一次最终检查必须使用同一上下文、请求及一个新的至多5秒固定期限，重新取得控制条凭据和设备门，检查原目标、版本、完整几何、安装授权、敏感状态及遮挡。属于原所有者的尝试遇到忙碌、过期或失效仍被消耗，不能续期重试；单独调用此只读 helper 不证明用户已审阅或宿主已移除。

`CapturedImageReviewCoordinator` 已实现内部顺序：在原服务显示真实安全浮层，实际批准后消费同一 PNG，立即固定新的5秒期限，等待该宿主的 `whenRemoved()` 和同一已批准窗口从系统窗口表中消失，再做一次最终检查并返回 `LocalToolResult`。此期限覆盖移除、最后检查和结果交付，不延长原捕获许可或60秒审阅会话。等待界面不占设备门，不替换任务取消钩子；排队或显示期间取消只能清理自己的宿主。所有失败关闭未移交 PNG，工厂交接后仍复核原代次、配置和时限。该接口现已接入带原任务资格的内部类型化适配器；普通启动仍不提供截图工具，权限仍关闭，真实生产链路尚未验收。

第四十五轮的三个实际失败确认了移除发布延迟：API35/36/37的被拒快照仍含同一已验证审阅窗口。新增等待只读取窗口元数据，实际批准时经私有不可变对象交接历史身份；真实View清理确认后，只有该ID的类型、显示器和边界仍完全一致且其他检查都有效时才等待。目标、控制条、新宿主、未知遮挡或上下文变化立即拒绝；对象逐项回收后释放设备门，轮间等待不占门。原消费后的5秒期限不续期，最终快照不排除该ID、不更新版本也不重试。APK及lint通过，8项实际交接回归已在第四十六轮高API32次通过、低API32次验证不支持；平台同步调用无法中断时仍由原工作线程持门到真正返回。

### 已实现的自有控制窗口身份

`AgentAccessibilityService` 只从其自身创建并持有的已附着控制 View 读取平台窗口 ID，登记窗口 token、默认显示器与连接／附着代次。主线程发布不可变的身份和几何；紧凑动作控制许可另行绑定该身份，展开确认面板不会自动成为可执行动作的凭据。布局、可见性、回调、移除与重连使旧凭据失效；缺失身份时只能在原任务约束和五秒内部期限内等待，不按标题或包名寻找替代窗口。每帧只复用登记并检查本地布局，不每帧构建无障碍节点。

普通观察和写前快照都用新鲜平台窗口列表核对：同一 ID 必须唯一，类型必须为无障碍浮层，位于默认显示器、不占输入焦点，且边界与自有 View 的登记几何一致。只有通过上述检查的控制窗口才能从未知遮挡中排除；其他同标题、同包名窗口仍算遮挡。读取完成及返回前再次检查身份有效性，检查与系统窗口变化仍非原子事务。

四项新增仪器回归使用真实附着窗口验证正常身份、同名未登记浮层、移除重建及首次布局前拒绝，已在第二十九轮八档全部通过，共32次；该轮的八次旧断言失败完整保留，修正后已复测。第三十二轮完整矩阵1016项通过，包含扩展后的五项窗口身份回归共40次，以及同值发布不撤销在途操作的正向验证。历史输入法窗口差异仍待定位。该身份仅对应任务控制条；现有图片审阅浮层使用另一个独立身份，不借用控制条登记，也不据此开放截图、手势或目标应用截图许可。

### 任务级合成图像资格基础

Controller提供显式的本次任务诊断参数，既有启动重载默认关闭，因此普通任务不会增加图像请求。选择该内部参数时，在原任务工作线程、原保存配置许可和启动时的执行代次下进行一次真实合成色块测试；它消耗同一任务的模型轮次与活动时间，使用保存的输出Token上限，不另建预算或继承设置页的历史成功提示。

成功记录仅由原任务持有；后续真实探测替换记录、暂停后继续、配置变化或到期均使其失效，不自动重测。探测未通过、网络失败或探测器正忙时给出一次固定说明，继续结构化流程；停止、预算耗尽和配置失效仍结束原任务，不能当作普通诊断失败吞掉。任务结束释放所持资格引用，进程探测器沿既有机制在下次检查时清除失效记录，不保留图片或密钥。

这是后续生产接线的内部基础：当前没有新增可操作的视觉开关，`take_screenshot`仍不提供给模型，服务截图权限和手势能力仍未开放。新增六项仪器回归使用实际加密保存配置、同一回环HTTP端点和真实PNG/nonce算法，覆盖默认关闭、原任务身份、资格替换、暂停/取消/配置变化、轮次预算及BUSY隔离；主程序、测试APK和lint通过；第四十九轮八档模拟器新增资格回归48/48通过，完整1880项通过并归档。未据此开放生产截图或宣称真机及真实模型通过。

### 截图路径仍需满足的条件

**内部模块已经实现不等于这些开放条件已经验收。** 生产入口、页面支持范围、真实捕获至模型的完整链路及真机资源测量仍有缺口，不能只修改权限声明就开放。

1. **先确定受支持应用与页面边界。** 明确怎样识别不可披露的页面，覆盖平台隐藏的敏感节点、自绘界面和动态变化。任意授权应用都可截图的通用安全判断目前没有可靠依据；只增加密码关键词不能补足该缺口。
2. **将实际图片审阅接入受支持页面的生产流程。** 内部宿主和交接已实现，用户须看到同一 PNG、目标应用与固定模型接收方并单独批准。仍需验收生产 Controller 与模型能力策略；密码、安全页面和未经授权内容不因通用开关或本地审阅而放行。
3. **仅在 API 34+ 请求目标窗口。** 内部前置守卫已检查亮屏解锁、原任务/代次、安装身份、唯一授权焦点、完整观察与未知遮挡；已知敏感或高影响页面拒绝。但无敏感节点的树、测试桥的成功或本地审阅，均不能替代第1项页面边界。
4. **验收完整前后与披露守卫链。** 既有内部快照、收据和最后检查仍须在实际生产连接中验证：切换、旋转、锁屏、暂停、撤权或配置变化后不得发送，系统安全窗口拒绝不重试绕过。普通结构化版本不证明自绘像素未变；真实模型理解质量和捕获后安装身份变化的独立集成样例仍待验收。
5. **保持容量准入并测量实际资源。** 单捕获槽、共享24 MiB已知持有容量、各阶段预约及失败排空已接线；原始stride、平台编解码器、渲染器与GPU实际峰值仍须测量。不能把逻辑计数当作物理上限，或以随后回收掩盖超额分配。

现有转换已实现显式软件复制、回收硬件包装和关闭原始缓冲后再缩小编码；真正的设备内存峰值仍待测量，高分辨率窗口可能在准入时直接拒绝。系统 API 没有请求低分辨率窗口捕获的参数。

图像处理使用有界工作队列，平台回调只移交或关闭句柄；平台提交及完整快照在受设备门保护的工作线程执行，主线程只发布轻量窗口身份和处理原生审阅界面。调用者可因原代次失效而结束等待，仍在执行的同步调用不会因此释放设备门或资源。平台截图没有公开取消接口，因此迟到回调必须自行关闭缓冲；位图编码的原生调用不能假定会被 Java 线程中断，取消后丢弃输出并完成回收，期间不得再排入图片工作。

## 4. 坐标能力单独验收

当前 `revision` 来自结构化节点与窗口几何。画布、视频或自绘页面可以在这些字段不变时改变像素，因此 **同一 `revision` 不等于同一视觉目标**。

现有 `resolve_node_at` 已提供“坐标定位到唯一可验证的无障碍节点”的只读受限方式；取得候选后仍须另行调用既有节点动作，不能把节点滚动冒充任意路径滑动。找不到唯一目标、页面截断、敏感或高影响目标、遮挡及控制条碰撞时拒绝。

真正的坐标手势还需独立契约与测试：图片坐标到屏幕坐标的确定映射、捕获标识、几何与短期有效性、点位或路径的用户确认、最终窗口复核及一次提交记录。放大、多窗口、画中画、旋转、非零窗口原点等未经验证的情况应降级，不能只按图片宽高比例猜测位置。

即使增加以上检查，普通 APK 的检查与全局触摸注入仍不是原子操作；无法确认目标时继续拒绝。手势完成回调只代表系统手势结束，业务结果须重新观察。暂停发生在提交后且结果不明时报告 `OUTCOME_UNKNOWN`，不重发。

先报告逐项测试结果和实际支持范围，再决定是否开放。模拟设备返回图片、核心测试通过或模型服务接受 `image_url`，均不能代替 Android 隐私边界、真实图像理解或真机性能验收。

### 图片专属发送条件

类型化本地工具结果可携带一个纯内存`DisclosureGuard`，与同一PNG所有者一起传给唯一下一次模型请求，不写入工具元数据、历史或持久化。请求上下文保留原配置守卫，并在既有构建、分块编码、排队、发送和回复采用边界复核图片条件。失败只终止匹配的原任务代次，不取消恢复后的新代次；旧接口和普通文本请求保持原行为。

发送条件失效不代表已经发出的字节可以撤回。实际网络线程退出前继续持有在途正文，取消回调不提前擦除其缓冲；不新增图片复制、重发或监听线程。15项新增核心用例含真实HTTP链路，完整282项通过；Android实际图片捕获、页面策略与审阅后的生产接线仍待验证。

### 服务事件代次与最终快照

实际服务发布纯内存事件代次。相关已送达窗口、内容、文本、滚动、焦点等事件，及实际自有窗口附着/几何/可见性、服务/显示变化会使旧代次失效。只对当前实际自有窗口的固定文案事件做排除，同时核对登记、token、窗口类型、标志与实时稳定几何；包名、标题或退休窗口ID均不能建立排除资格。一个服务生命周期级显示监听随连接注册、断开注销，不为每张图建立监听器或线程。

审阅结束后的原单次最终快照固定读取前的代次，复用原截止时间，在慢检查前后核对，变化即拒绝，不重复快照或续期。返回的本地guard只读取原owner/epoch/lease、exact服务及事件代次；任务预算仍由原请求上下文检查。纯文字更新可能清空动作布局凭据，但不等同于窗口已移动，图片guard因此使用实际登记与事件代次；真实尺寸变化仍同步失效。第五十一轮新增5项回归在八档40/40通过：低API的16项只验证不支持，其他24项使用实际窗口或合成图像来源。该轮另有API31输入法窗口一致性失败；不据此声称完整矩阵或生产图像外发通过。

事件送达、最终快照与网络写入并非原子过程，未上报的像素变化或尚在排队的事件不在此机制保证内，已经发送的字节不能撤回。固定支持页面、逐图实际审阅和原任务资格仍是后续生产接线的独立条件；当前权限保持关闭。


### 固定页面与类型化截图适配器

内部任务在原保存配置、任务对象与执行代次下完成一次合成图像资格检查后，可准备固定页面策略。安装文件摘要只在这次准备中有界读取一次；后续阶段检查安装元数据，不在主线程或HTTP发送守卫里重复扫描APK。暂停时丢弃原资格，恢复不会重新探测或提升权限。

首个候选仅匹配指定签名与文件摘要的计算器普通竖屏算术页，见[固定页面源码与边界](VISUAL_SUPPORTED_PAGE.md)。策略使用原完整快照持有的节点，限制原生角色、资源ID、几何、文本及额外内容；在准备、提交前、实际捕获后和审阅后的单次最终快照中一致核对。菜单、历史、设置、换算器、未知绘制和不完整观察均不属于支持页。

类型化工具调用保留完整原请求和owner，经平台窗口捕获、PNG转换、实际逐图审阅及移除确认，将同一PNG连同最终失效守卫交给下一次模型请求。旧字符串入口和错误owner不能取得该能力。没有增加截图或手势权限；实际连接服务没有截图能力、普通任务未明确选择图像诊断时，工具仍不可用。
