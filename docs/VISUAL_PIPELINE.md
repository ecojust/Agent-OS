# 受控视觉观察与坐标操作

本文是后续模块的实施边界。**当前 Android 执行器未开放 `take_screenshot`、`tap`、`swipe`，服务也未申请截图和手势能力。** 核心层的图片附件处理不代表设备截图已可用，不代表模型图像能力或真机视觉任务已验证。

授权、确认与执行代次遵守 [DESIGN_RULES.md](DESIGN_RULES.md)，资源上限遵守 [PERFORMANCE.md](PERFORMANCE.md)。已实现核心附件生命周期、受限的只读节点定位与独立合成图片探测；不增加设备截图或手势权限。

## 1. 已核实的平台行为

以下依据 Android 开源平台指定版本的实现；厂商实现和设备行为仍需实测。

| 平台行为 | 实施影响 |
| --- | --- |
| Android 14 / API 34 新增 `takeScreenshotOfWindow(windowId, executor, callback)`，返回指定窗口的图像；上方无障碍浮层不包含在目标窗口图像中。 | 后续优先使用按窗口路径；即使截图能看到遮挡下的内容，执行器仍须拒绝未知遮挡，不能借此读取当前不可观察的页面。 |

| 非辅助工具服务读取界面时，平台可直接过滤标为 `isAccessibilityDataSensitive` 的视图；窗口截图路径没有对应的逐视图遮罩。 | “无障碍树没有密码或敏感节点”不能证明图像没有敏感内容。不得设置 `isAccessibilityTool=true` 来绕过过滤。 |

## 2. 核心附件模块

该模块可先用合成图片和模拟设备工具验证，无须启用 Android 截图权限。

- 只有当前可用工具清单中的本机 `take_screenshot` 成功结果可以产生图片附件。模型返回的文字、其他工具结果或 URL 不能自行建立附件。
- 附件绑定原请求的 `taskId`、`profileId`、执行代次、`callId` 和 `expectedRevision`；结果中的 `data.revision` 必须匹配。不得在暂停恢复后为旧图片绑定新代次。
- 每次只保留一张待发送图片。图片不进入工具调用去重记录、普通工具文本、任务日志或长期对话历史；重复 `callId` 不再次附图。
- 附件仅供下一次模型请求消费，之后释放。观察刷新、界面写操作、暂停、停止、任务结束或配置变化使待发送图片失效；同轮后续操作也必须执行该规则。
- 首轮仅接受受限的单帧 PNG；JPEG 等格式待有界校验路径单独验收后再开放。检查实际内容与声明尺寸一致：编码数据至多 1 MiB、长边至多 1280 像素、总像素至多 1,048,576。限制检查先于大额解码分配；不以扩展名或 MIME 前缀证明格式正确。
- 网络失败不自动重发图片。清理本机引用不等于删除模型服务收到的数据；正在退出的网络请求可能短暂保留发送缓冲，不能宣称停止后立即物理擦除所有副本。

现有四参数设备工具接口仍以 `imageDataUrl` 返回本地图片，`data` 保存小型元数据；核心在进入去重记录前分离、验证并转为具有所有权的 PNG。发送时直接从 PNG 分块编码，不再把完整图片字符串加入请求消息对象。`windowId`、窗口边界、图像尺寸和 `captureId` 等元数据可为后续映射保留，但不能仅凭这些字段证明坐标可安全执行。实际 Android 截图适配器尚未接入，旧工具入口的字符串也尚未由直接 PNG 交接替代。

## 2.1 已实现的受限节点定位核心

`CoordinateNodeResolver` 是独立的只读候选解析模块，不生成触摸手势。输入坐标使用与 `observe.bounds` 一致的屏幕坐标像素，不接受 dp、归一化或缩放截图坐标，也不将其称作硬件面板像素。

请求绑定任务、资料、执行代次、包名、默认显示器、窗口、界面版本和窗口边界。完整且有界的观察中，只返回支持所请求节点动作的唯一候选；同动作歧义、截断、旧版本、敏感和未知遮挡均拒绝。模块不持有平台节点或页面文本，不授予任何执行权限；候选后续仍须走原有确认和最终设备校验。

滚动是既有节点动作，不是触摸路径：查询点必须在安全区域且不落在可信控制条上，容器完整位于窗口内并与安全内容相交；点击和文本候选还须完整位于安全内容中并避开控制条。所有动作均拒绝与未知遮挡或危险节点相交的候选。首批 17 项纯 JVM 测试通过；Android 已接入独立的只读定位工具；第十七轮的后续点击失效记录保留；第十八轮完整八档回归通过，正向用例仅在明确未派发后重新观察、重新解析并独立确认。不能据此宣称截图或坐标手势已经开放。

## 2.2 Android 只读节点定位工具

`resolve_node_at` 只接受最近一次成功 `observe` 的版本与屏幕坐标；`coordinateSpace` 必须显式为 `screen_pixels`，`action` 为 `click`、`type_text`、`scroll_forward` 或 `scroll_backward`。它不换算图片坐标，不点击、不输入、不滚动。示例参数：

```json
{
  "x": 120,
  "y": 280,
  "coordinateSpace": "screen_pixels",
  "action": "click",
  "expectedRevision": "从最近observe获取的版本"
}
```

结果包含节点编号、动作、边界、窗口及原版本，明确标记 `candidateOnly`、`requiresConfirmation` 和未提交。取得候选后，模型仍需发起既有节点工具调用，由原有确认和最后检查决定能否执行。候选不更新规划器的观察版本；同一模型计划已经写入或取得图像时，继续定位会被拒绝并要求重新规划。

平台适配器在同一工作线程使用新快照，核对授权、平台实际支持的动作、控制条凭据、窗口和原执行代次。当前仅默认显示器可用，已知敏感页面、未知窗口遮挡与不完整观察拒绝。实际支持的点击、文本设置及滚动方向参与观察版本，能力变化也使旧计划失效。

## 2.3 图片审阅会话核心

`PngImage` 持有经过有界校验的最终 PNG，不接受后续内容修改；预览与消费来自同一份编码。共享校验器检查文件结构、校验和与实际解压行数，编码上限仍为 1 MiB、长边 1280 像素、总像素 1,048,576。校验直接从原 PNG 的每个 IDAT 片段向解压器供给数据，保留一个固定 8 KiB 输出缓冲，不再聚合压缩数据或复制整份 IDAT。成功和异常出口清理输出缓冲并关闭解压器；先分配 Java 缓冲再创建解压器，避免缓冲分配失败遗留无所属对象的 native 实例。调用者和渲染器的副本仍需各自释放，这不等于整个流程满足 24 MiB 实际峰值。

`ImageReviewSession` 只管理一次本地审阅，既不捕获设备，也不发送网络请求。它绑定任务、资料、原执行代次、调用、捕获、安装身份、窗口几何、观察版本，以及不含密钥的模型接收方和配置标识。可信宿主取得一次带生命周期的只读预览流并实际呈现后，才能取得独立图片许可；该许可不接受文字确认，也只能消费一次原 PNG。

60 秒有效期从创建开始计算，准备图片和确认不会重新计时。拒绝、超时、宿主失效、暂停、停止、配置或绑定变化使未消费图片失效；旧宿主回调及其他会话的许可不能操作新会话。会话不覆盖模型请求的取消钩子，宿主负责独立调度到期清理，控制器须在状态变化时及时通知。

新增 16 项 JVM 测试通过，该模块提交时完整核心测试为 129/129；原图片附件测试仍通过。控制器接线、实际窗口捕获及最终发送守卫尚未验收，工具和平台权限保持未开放。核心有界校验不等于整个捕获与渲染流程已经满足 24 MiB 图像工作集预算。

后续流式校验优化新增 12 项 JVM 回归，覆盖 IDAT 任意分界、空块、跨块尾随数据、拼接压缩流、截断、行过滤和解压量限制；该优化完成时完整核心测试 180/180 实跑通过。Android 主程序、仪器测试编译及 lint 通过，并已包含在第二十八轮八档完整通过的模拟器矩阵中。优化减少的是确定的压缩副本，不是设备内存测量结果。

## 2.3.1 已知图片缓冲容量与读取者生命周期

`ImageWorkset.process()` 为进程内已知、由应用持有的图片缓冲容量提供共享 24 MiB 准入。PNG 工厂在复制调用者输入前预约编码容量和固定校验缓冲；验证成功只保留编码预约，失败或 Error 出口归还未移交资源。模型请求的最终 UTF-8 正文也使用同一池；调用者源数组、既有 Base64/dataURL 字符串、JSON 对象、编码器／HTTP 内部缓冲、GC、平台解码器及 GPU 不包含在计数中，不能将它称为全流程物理内存上限。

`PngImage.openRead()` 返回不暴露内部数组的 `ReadLease`，支持在同一份只读编码上读取、定位和重读。关闭 PNG 所有者立即阻止新读取者；已经开始的读取者可以完成解码，直到最后一个流关闭才擦除编码并归还其预约。读取者关闭幂等，转交已确认的 PNG 不复制、不重复计费；消费者自己的输出缓冲需自行管理。审阅会话只签发一次 `openPreviewRead`，仍校验宿主、原代次、绑定、配置与时限。构造异常也会结束已经开始的审批等待，避免活动计时停留在等待状态。

新增 19 项核心回归覆盖共享准入、溢出、重复关闭、复制前拒绝、分配与验证异常、原数据隔离、在途读取、mark/reset、关闭和一次许可移交；该模块完成时完整核心测试 **199/199 实跑通过**。这验证资源所有权协议，不代表设备内存峰值验收。

模型网关随后增加独立请求正文所有权：保留私有 JSON 快照，在工作线程两遍编码，第一遍有界计算实际 UTF-8 长度，第二遍在预约后直接写入精确数组，核对两遍长度和摘要。最多 4 MiB，沿用原 JSON 转义和 Unicode 行为，不生成完整的中间 JSON 字符串。正文移交给具有 `PENDING / RUNNING / RELEASED` 状态的网络任务；排队但未运行的任务由调用工作线程撤销，在途任务只由原网络工作线程退出时擦除并归还。Future 已取消、调用者已返回或连接正在断开，都不代表可以提前释放正文。同步取消钩子只取消、移除排队任务并安排断连，不擦除大缓冲。

任务图片发送已进一步改为强类型分块编码。`ImageAttachment` 持有已验证的 `PngImage`，按原任务、资料、代次及观察版本只转交一次；Runner 在准备消息与工具定义后交给 HTTP 请求，请求从最外层异常出口负责关闭 PNG。编码结束便释放原图，进入网络队列的只有最终正文；取消请求仍须等在途网络线程退出后擦除正文。

本地旧 dataURL 入口按字符读取 ASCII，经标准 Base64 解码流写入预约后的临时数组，不创建完整 substring 或额外的完整 ASCII 数组；保持缺省补位兼容，拒绝补位后尾随字符。临时解码数组、不可变 PNG 副本和校验暂存同时计入准入；临时数组擦除后才归还额度。原始 JSON 字符串仍由调用者持有，不声称能够擦除它。

`ImageRequestSerializer` 仅写入本方固定的图片消息结构，普通 JSON 字段继续使用原有 Gson 设置；不通过查找或替换文本占位符插图。一个只读流跨两遍复位，3 KiB输入及4 Ki字符输出共11 KiB固定暂存在分配前预约，编码块之间检查配置和任务。最终正文仍受4 MiB限制及两遍长度、摘要一致性校验，图片不进入对话历史或重放记录。

新增10项 JVM 回归覆盖所有补位长度、跨块数据、原 JSON 字节兼容、精确大小边界、预算不足、编码中取消、异常清理和真实 HTTP 在途所有权；完整核心 **223/223 实跑通过**。另新增1项 Android 回归使用公开 Runner、合成 PNG 和四轮真实回环 HTTP，由平台解码器独立核对像素、UTF-8以及后续历史不含图片；测试 APK 编译与 lint 通过，第三十三轮新增8次执行全部通过，该轮完整矩阵1024项全过。此优化仅针对任务附件路径，独立 `VisionModelProbe` 的合成图仍使用既有 dataURL；JSON 对象、编解码器及 HTTP 内部副本、GC和GPU不包含在容量计数中。

## 2.4 原生图片审阅组件

`ImageReviewView` 显示目标应用包名、完整模型接收方和同一最终 PNG 的预览，支持通过矩阵缩放和平移查看图片。确认按钮仅在图片解码、挂载和可见布局完成后启用。工作线程负责解码；主线程只挂载不可变位图，不重新截图或编码。已交给渲染器的位图先断开 Drawable 引用，不在后台强制回收仍可能绘制的位图。

内部 `SecureImageReviewDialog` 要求宿主窗口和自身窗口均保留 `FLAG_SECURE`。进程同时只接纳一个审阅宿主和一个解码/待挂载结果；过期、失焦、销毁、配置变化或内存压力会撤销尚未消费的许可。拒绝新宿主时清理新会话，重复的未显示窗口不能撤销实际宿主；迟到解码结果丢弃并释放。非主线程关闭先同步使已持有的许可失效，再安排界面清理。

预览解码前从同一共享池预约 4 MiB 已知像素容量和 16 KiB 显式 `inTempStorage`，直接消费只读 PNG 流；临时缓冲在解码返回后擦除并归还。输出继续核对尺寸、ARGB_8888、不可变性及 `getAllocationByteCount()`，超过预约则拒绝，不把事后回收写作没有超限。`DecodedPreview` 将像素预约从工作线程移交到主线程和 View；迟到且未展示的结果可以回收，已经交给 View 的图像先解除引用，只归还本方所有权额度，不能由此证明 RenderThread 或 GPU 已释放。单工作线程、单预览准入和容量为一的交接队列限制并发，原线程仍在退出尾部时也不会错误拒绝下一次已准入工作。

新增五项真实 Android 仪器测试检查预算不足时不调用解码器、失效后的在途读取、待主线程消费结果的额度、已展示 Bitmap 不强制回收，以及解码异常后的下一次预览。主程序、测试 APK 和 lint 通过；第二十八轮八档新增 40 次执行全部通过，该轮图片审阅合计 112 次通过，保护窗口的采集保持 blocked。

该组件尚无生产入口。把应用 Activity 切到前台会改变原任务焦点，所以不能把内部 Dialog 的测试当作第三方目标仍有效的证明；生产接线须使用受控的审阅宿主和实际窗口守卫。新增九项仪器测试已在第十八轮八档模拟器通过，主程序编译和 lint 通过；保护窗口的截图采集明确记录为 blocked，不临时清除安全标志来生成界面证据。

## 2.5 独立合成图片能力探测

`VisionModelProbe` 只发送临时生成的 512×256 PNG：两行四列的八种颜色随机排列，带有清晰的中灰边距。提示和参数定义给出可用颜色名及一次随机 nonce，不包含正确排列；必须依据实际图片返回完整顺序。仅校验一次无副作用的探测工具回复，不执行任何模型要求的设备操作，也不读取任务、资料标识或应用内容。

网络响应、工具协议与合成图片校验分别报告，正确回复仅表示这一次合成图片测试通过。它不能证明任意真实界面的理解质量，不自动开放截图工具。沿用现有取消、时限及不重试策略，取消和旧代次继续作为中断处理；不转到其他模型服务。

新增 17 项真实本地 HTTP 测试，从实际请求中的 PNG 独立解码并构造答案，覆盖错误排列、旧 nonce、非法参数、错误响应、重定向、取消和超时。完整核心测试 146/146 实跑通过；真实模型服务尚未验收。

原生模型配置页已提供独立的“测试图像理解”入口。连接、工具、合成图像三项结果分别显示，同一配置的图像测试不会把工具测试自动标为通过；任一连接字段变化会取消旧请求并清除验证结果。一次点击仅发起所选择的探测，沿用取消按钮与本地 HTTP 信任确认；旧提示框不能授权后来修改的地址或配置。新增七项原生仪器测试，使用真实回环 HTTP 服务解码 PNG 像素并返回答案；主程序、测试编译及 lint 通过，七项用例已在第十九轮八档模拟器通过。受保护配置页面不临时解除安全标志采集截图。

## 3. 开放设备截图前的最小条件

### 已实现的自有控制窗口身份

`AgentAccessibilityService` 只从其自身创建并持有的已附着控制 View 读取平台窗口 ID，登记窗口 token、默认显示器与连接／附着代次。主线程发布不可变的身份和几何；紧凑动作控制许可另行绑定该身份，展开确认面板不会自动成为可执行动作的凭据。布局、可见性、回调、移除与重连使旧凭据失效；缺失身份时只能在原任务约束和五秒内部期限内等待，不按标题或包名寻找替代窗口。每帧只复用登记并检查本地布局，不每帧构建无障碍节点。

普通观察和写前快照都用新鲜平台窗口列表核对：同一 ID 必须唯一，类型必须为无障碍浮层，位于默认显示器、不占输入焦点，且边界与自有 View 的登记几何一致。只有通过上述检查的控制窗口才能从未知遮挡中排除；其他同标题、同包名窗口仍算遮挡。读取完成及返回前再次检查身份有效性，检查与系统窗口变化仍非原子事务。

四项新增仪器回归使用真实附着窗口验证正常身份、同名未登记浮层、移除重建及首次布局前拒绝，已在第二十九轮八档全部通过，共32次；该轮的八次旧断言失败完整保留，修正后已复测。第三十二轮完整矩阵1016项通过，包含扩展后的五项窗口身份回归共40次，以及同值发布不撤销在途操作的正向验证。历史输入法窗口差异仍待定位。该身份仅对应任务控制条，不包含未来图片审阅浮层，也不开放截图、手势或目标应用截图许可。

### 截图路径仍需满足的条件

**这些条件是待实现和待验证的设计，尚非当前能力。** 只完成 SDK 版本判断和权限声明不足以开放功能。

1. **先确定受支持应用与页面边界。** 明确怎样识别不可披露的页面，覆盖平台隐藏的敏感节点、自绘界面和动态变化。任意授权应用都可截图的通用安全判断目前没有可靠依据；只增加密码关键词不能补足该缺口。
2. **设计本地实际图片审阅。** 用户看到本次将发送的图像、目标应用及模型接收方，再单独确认披露。确认绑定不可变图片和服务配置，不只显示“允许截图”文字。密码、安全页面和未经授权内容不因用户开启通用开关而放行；图片审阅也不替代这些边界。
3. **仅在 API 34+ 请求目标窗口。** 前置条件包括亮屏解锁、同一任务与代次、安装身份仍有效、唯一授权焦点窗口、完整且有界的观察、无已知密码或敏感节点、无未知遮挡。截断观察不能用来证明不存在敏感内容。
4. **前后复核并丢弃失效结果。** 截图前后及披露前重新校验授权、窗口、几何、`revision`、代次与配置；窗口切换、旋转、锁屏、暂停、撤权或预算超限时不发送。系统安全窗口错误直接拒绝，不尝试绕过。
5. **限制工作集和并发。** 同时最多一项捕获或编码任务。请求前保守核算原始缓冲、软件复制、缩小图、预览及编码的阶段峰值，遵守 24 MiB 图像预算；返回后复核实际尺寸和格式。超出预算时禁用该次图像路径，不以稍后回收掩盖超限。

可评估的内存实现是：包装硬件缓冲，显式复制为软件位图，立即回收原始包装并关闭缓冲，再缩小和编码，避免全尺寸图与多份缩小图同时存活。该路径仍需实际测量；高分辨率窗口可能必须降级。系统 API 没有请求低分辨率窗口捕获的参数。

截图回调和图像处理使用有界工作队列；主线程只负责必要的平台提交、轻量校验和原生确认界面。所有等待可因原代次失效而退出。平台截图没有公开取消接口，因此迟到回调必须自行关闭缓冲；位图编码的原生调用不能假定会被 Java 线程中断，取消后丢弃输出并完成回收，期间不得再排入图片工作。

## 4. 坐标能力单独验收

当前 `revision` 来自结构化节点与窗口几何。画布、视频或自绘页面可以在这些字段不变时改变像素，因此 **同一 `revision` 不等于同一视觉目标**。

优先评估“坐标定位到唯一可验证的无障碍节点，再执行已有节点动作”的受限方式；需要明确工具语义，不能把节点滚动冒充任意路径滑动。找不到唯一目标、页面截断、敏感或高影响目标、遮挡及控制条碰撞时拒绝。

真正的坐标手势还需独立契约与测试：图片坐标到屏幕坐标的确定映射、捕获标识、几何与短期有效性、点位或路径的用户确认、最终窗口复核及一次提交记录。放大、多窗口、画中画、旋转、非零窗口原点等未经验证的情况应降级，不能只按图片宽高比例猜测位置。

即使增加以上检查，普通 APK 的检查与全局触摸注入仍不是原子操作；无法确认目标时继续拒绝。手势完成回调只代表系统手势结束，业务结果须重新观察。暂停发生在提交后且结果不明时报告 `OUTCOME_UNKNOWN`，不重发。

## 5. 验收分工与开放标准

| 模块 | 最小交付与验证 |
| --- | --- |
| 核心 | 单次附件、大小和绑定校验、去重、历史隔离；覆盖同轮截图后写操作、重复调用、旧代次、异常和取消清理。 |
| 原生界面与控制器 | 实际图片与接收方审阅、一次确认、配置绑定；暂停或确认过期后不能发送。独立会话和原生组件已实现，合成内容的八档模拟器测试通过，生产控制器接线与真机验证待完成。 |
| Android 设备适配器 | API 34+ 窗口捕获、前后守卫、回调回收和内存预算；API 30–33 明确降级。权限变更与工具开放须在条件满足后单独提交。 |
| 平台测试 | 安全窗口、普通密码及平台隐藏敏感视图、自绘内容、其他窗口遮挡、焦点变化、旋转、锁屏、撤权、迟到回调和大窗口内存。使用合成内容，不上传真实个人界面。 |

先报告逐项测试结果和实际支持范围，再决定是否开放。模拟设备返回图片、核心测试通过或模型服务接受 `image_url`，均不能代替 Android 隐私边界、真实图像理解或真机性能验收。
