## Minimum runtime predicate

Implement a bounded, package-private `SupportedVisualPagePolicy` used by the existing complete Snapshot while the existing device gate is held. It returns a small immutable policy ID/fingerprint, never a model-controlled permission and never a generic “safe” Boolean. Do not query PackageManager or Views from the HTTP disclosure guard.

All conditions below must hold together:

1. Existing API34+, original control/epoch, real saved lease, exact app grant, supported capture capability, screen unlocked, same live service, owned controls and original task-qualified model checks remain mandatory. No string-only tool call, UI-probe success Boolean or model-supplied package/page name can issue the permit.
2. One input-focused TYPE_APPLICATION window on the default display; original window ID/display/rotation and full-window/root bounds must agree. For this first entry require portrait, full-display application geometry and a complete root covering that window; reject freeform, split screen, PiP, clipped/zero-size or transitioning windows. Compare actual platform bounds, not fixed device pixels. Existing safe-content/system-bar and actual-owned-control handling remains unchanged.
3. Complete bounded tree, with no truncated node text, password node, API34 accessibility-data-sensitive node/subtree, editable text field, known high-impact state, or unknown overlapping window. A missing required node is a rejection, not permission to assume the platform filtered harmless content. Preserve native secure-window refusal without retry/fallback. Root reads for this predicate must use the actual already-owned node data, not model-visible truncated JSON.
4. The basic keypad anchors below occur exactly once in the target window, belong to the exact target package, are visible/enabled/noneditable/nonpassword, have nonempty bounds contained in the calculator content, and are not covered by an unknown window. Formula and result report the native text role (`android.widget.TextView`); the 20 keypad controls report the same text role and expose click. Their original text must be complete and bounded. Do not accept an arbitrary class that merely contains “Text”.
5. Formula/result and every keypad control share the `calculator_holder` region and have the reviewed portrait structure: formula above result, both above five four-key rows. The 20 button rectangles are distinct, ordered by row, nonoverlapping and within the holder/safe content. Permit normal density/font/layout scaling, not a screenshot-coordinate template. The invisible `btn_reset` must not become a visible 21st keypad control. Enclosing resource anchors (`main_coordinator`, `main_appbar`, `main_toolbar`, `main_nested_scrollview`, `calculator_holder`) must be consistent when exposed. ## Explicit rejections and bounded meaning

Reject history (`history_list`/history item content), any AlertDialog/popup/menu/floating action mode, converter, settings/customization/about/FAQ/donation/new-version UI, widget, notification/clipboard/IME or other unknown overlapping layer, another application, unsupported orientation or missing anchors. A toolbar button existing on the ordinary page is not itself an open menu; do not make the normal screen impossible by banning the `history` button.

A no-password tree is not a universal pixel guarantee. The positive reason here is a fixed audited application/rendering path plus the complete narrow page predicate; missing/hidden required nodes and any exposed sensitive nodes reject. An application version with a new custom renderer, secure field or sensitive subtree is outside this exact binary entry. A separately signed synthetic fixture with matching IDs is not a production positive case.

Formula/result can encode private amounts, phone numbers or history-derived values. The whole exact PNG is shown with the fixed recipient, and may be declined. Do not record those display values or images in diagnostics. Custom fonts/colors are user-selected presentation and may make visual glyphs differ from accessible text; this policy approves the **current rendered image**, not a claim that every glyph was supplied by the APK. Global font/style/private prefs are neither read nor changed.

Window metadata, accessibility events, native capture and network writes are not atomic. Keep existing epoch/config/page/revision checks and observed-event revocation; reject a known change, clear unsent pixels, and do not claim to retract bytes already sent. Historical emulator evidence of an unreported IME remains an explicit platform limit; do not treat a missing TYPE_INPUT_METHOD record as proof that no keyboard exists. The audited basic page has no editable field or code path that requests the IME, which narrows ordinary exposure without solving arbitrary platform omissions.
