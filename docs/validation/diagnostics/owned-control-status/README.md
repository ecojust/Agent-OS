# API30 控制状态失败现场

[清单](manifest.json)保存三次原专项API30任务的来源、精确源码、原日志摘要、行号及摘录文件大小/SHA-256。每份txt是`gh run view --job --log`返回中首次原身份等待AssertionError及紧随的调用位置，文字与时间戳保持原样；它们是诊断摘录，不是完整JUnit或新的测试执行。

- [40617441495](40617441495-api30.txt)：原五秒身份等待失败，取消后取得的状态与几何一致。
- [40618062095](40618062095-api30.txt)：发布3ms，实际身份等待4997ms，在5000ms失败。
- [40618768617](40618768617-api30.txt)：发布2ms，5000ms失败；取消后5000–5001ms的主线程栈位于平台无障碍缓存事件处理，5004ms采样到一致身份。

这些是顺序采样。失败后的身份不能证明原期限内已就绪，单次线程栈不能证明整个五秒期间的等待链。原截图与每档结果分别见`screenshots/<run>-1/`，三轮均7/8，不替代完整回归。
