# 连续导航来源拒绝的前置验证与诊断

本模块针对[源码31e1的API35原始失败](diagnostics/navigation-origin-40698819944/README.md)补齐测试证据。该次完整矩阵为2111/2112通过：导航来源拒绝用例只记录了“未抛预期暂停异常”，没有保存调用返回值，也没有确认实际前台是设置页。不能据断言文案认定曾经发生越界启动。

## 验证目标

测试通过现有PackageManager能力解析`ACTION_SETTINGS`，核验可用系统应用并排除Agent、Fixture、默认桌面及歧义解析产生的resolver占位。HOME和Settings各自的解析组件必须在同Intent最多32个真实候选中精确匹配一次；允许存在多个候选且已选定真实默认组件。保持原隐式设置启动，实际观察与独立聚焦窗口必须对应解析出的设置包，窗口ID与根节点ID也须一致。无法确认时作为前置失败，不增加生产包可见性权限，也不伪造窗口或观察结果。

单次`launch_app`仍必须抛出`TASK_PAUSED`，随后满足原有暂停、零审批、零设备派发、焦点不变、无派发trace和零HTTP请求断言。普通返回包括`STALE_OBSERVATION`均保持失败，不通过重放动作或放宽断言使结果变绿。

失败诊断在资源清理前采集固定元数据：调用阶段、白名单错误码、返回布尔的真实类型与缺失状态、执行代次、暂停与取消状态、派发和请求计数，以及有界trace计数与前台身份分类。正常accepted返回可以没有`code`，因此缺失不得伪造为某个错误码。最终快照trace事件存在也不等于成功到达来源检查，需区分快照是否完成；不输出页面文本、任务目标、返回JSON全文或任意异常消息。

用例主体的诊断附在原失败上，保留原异常及清理语义；固定JSON严格小于2000字符，超限或采样不可用时只保留固定标记，不覆盖原异常。产品的导航授权、来源检查、控制条、执行通道和安全窗口均不修改；即使本轮通过，也不倒推历史失败根因。
