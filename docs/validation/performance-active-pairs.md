# 活跃任务等价对照

本任务比较同设备上完成相同Fixture目标的两条路径，属于[性能后续任务](../PERFORMANCE.md#性能后续任务)。实现与本地验证已完成，尚无本轮设备实测结果；原检查点10/20（50%）及已归档压力结果保持原验收范围。

## 固定计划与等价目标

独立`active-pair-diagnostic`专项在API30、31、32、33、34、35、36、37.0各执行一项测试。每API固定六对，顺序为AC、CA、AC、CA、AC、CA，每组五个独立任务；共 **48对、96组、480任务**，其中A/C各240任务。首个失败即停止，不替换失败任务，也不丢弃第一对。原273项/API完整矩阵排除此独立探针。

- **A：Agent服务关闭，脚本操作真实控件。** 使用UiAutomation新取的Fixture节点，依次设置文本、点击保存、点击计数按钮。每个写操作只提交一次，返回失败或结果未知即结束，不重放计数点击。这是脚本化人工等价目标流程，不是真人、物理触摸或IME输入测量。
- **C：服务开启，Agent执行同一目标。** 使用真实Controller、保存配置与本地SAVE_AND_COUNT模型，按当前确认ID逐次批准。要求真实终态及结果码MODEL_REPORT、模型收到三次接受写入，以及独立UI核对。合法的未派发旧观察重规划可能需要额外确认，保留实际确认次数和生产预算。

每个任务都重新创建Fixture页面，核对空输入、`Saved: empty`及`Count: 0`；最终核对相同输入、保存内容和`Count: 1`。两组使用相同的本地服务器与配置准备，A服务器保持零请求，C通过其实际HTTP模型链路；A平台动作接受次数与C模型确认的写入次数分列，不混作同一种计数。计划分别为720次A平台接受、720次C模型确认写入，最终结果均另有UI核对。

两组共用服务切换与Fixture准备逻辑，不创建会主动显示测试控制条的DeviceHarness；C由生产Controller建立实际控制条。原服务列表、启用值、UiAutomation标志与配置均恢复。不开启额外免确认路径，不清安全标志、不强制GC、不覆盖系统动画。

## 测量边界

服务连接、Fixture重建、本地模型及配置准备、两秒固定稳定等待、截图和清理均在任务计时之外。任务计时从即将执行目标开始，到实际终态和独立目标结果核对结束；两组分别保存单调时间和进程累计CPU毫秒。主指标为 **每任务CPU毫秒、实际任务毫秒**，按五任务先汇总每组，再算配对C−A。

任务短时可能出现CPU差为0的量化结果，这是有效观测，不能补造精度。两组实际耗时不同，不以CPU百分比差宣称Agent净开销，不延长任务来凑采样窗口。

PSS仅在任务前后各采一次，并记录采样时间及耗时；PSS读取在任务CPU/时间边界外，无周期采样。后端点在Controller、服务器、配置清理前采集，trace JSON复制也在其后；测后服务/前台状态检查在清理后完成。记录前后绝对PSS、任务端点变化和配对端点差；这不是稳态活跃PSS、瞬时峰值或完整任务内存曲线。

当前测量的是驻留Agent仪器进程，包含测试驱动及C实际模型处理，不含Fixture或系统其他进程。两组都有测试服务器，但C的模型CPU仍是差异来源；前一组的服务或分配残留、缓存/GC、主机负载和顺序效应尚未独立控制。交替顺序与固定准备不能据此建立因果结论。模型、任务和确认预算沿用生产规则，专项继续使用20分钟外层watchdog和35分钟CI作业上限。

## 证据、失败与统计

每API逐任务原子写入`trial-000.json`至`trial-059.json`，根清单只保存小型引用，避免积累此前任务的完整trace。根清单开始为`incomplete`，每完成一项更新已提交前缀；60项和全部清理通过后才写最终`passed`。正常失败保存失败任务及后续未执行分母；被终止时，未提交部分记为未取得证据，不推断从未执行。

A执行trace必须为空，C保留生产观察、模型和派发trace，最多4096事件且通过记录不允许覆盖。根清单最多64KiB，单trial最多4MiB，单API附件最多256MiB；归档全局64MiB上限不变。采集器只读取根清单引用的文件，全部ADB读取合计至多60秒，逐项核验字段、顺序、时间、CPU、结果、长度和摘要。

统计始终保留8API、48对、96组和480任务分母。每对只有两组各五任务完整通过才进入配对差值计算；失败运行中已完成配对可描述，原运行/作业/Gradle结论不因此改变。按API分别报告全部六对以及AC/CA各三对的min/median/max，不把子任务视为独立设备、不报告P95/P99。原始端点、任务标记、引用摘要和统计工具摘要一并保留。

仅记录序列前后截图及失败现场；同源普通操作演示另行录制，不冒称本专项全程录像。旧四态未被本scope选择，其默认采集记录按原状保存，不作通过项。

本任务保持`diagnosticOnly=true`、`budgetAcceptance=false`。稳态与峰值PSS、目标进程、启动/完整帧、繁忙状态停止、真实模型和真机资源预算继续分别验收。
