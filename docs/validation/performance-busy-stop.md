# 受控繁忙状态下的停止响应

本项继续[性能后续任务](../PERFORMANCE.md#性能后续任务)，补齐实际停止按钮、在途平台调用及本地停止反馈的证据。Android 仪器编译、lint、Fixture 编译与 3 项探针单元测试已通过；默认完整矩阵的 273 个 class#method 身份与基线逐一相同。874 项完整宿主回归无跳过且全部通过，尚无本专项设备通过结果。既有等待确认时停止、直接取消 RunControl 的真实远端点击测试和核心取消单元测试保留原范围，不能代替本项。

本轮使用 API 30、31、32、33、34、35、36、37.0 八档专用合成模拟器，真实 Controller、生产授权与确认路径、固定本地 HTTP 测试模型和独立 Fixture APK。所有结果保持 `diagnosticOnly=true`、`budgetAcceptance=false`、`fullSuiteAcceptance=false`。受控等待不等于持续 CPU 满载，模拟器数据不代表真机、厂商 ROM 或 200 毫秒发布预算已经验收。

## 固定场景与样本计划

| 场景 | 必须实际到达的繁忙条件 | 停止入口 | 界面证据范围 |
| --- | --- | --- | --- |
| `DEVICE`（在途平台调用） | 获得确认的真实 Accessibility 点击已进入 SlowActivity 的 onClick，目标回调仍由有界屏障阻塞，原调用尚未返回 | 当前任务浮条的实际停止按钮，注入触摸 DOWN／UP | 控制状态与浮条宿主移除；不称为完整合成帧或屏幕呈现 |
| `MODEL`（回复等待中） | 本地 HTTP 服务已收到完整任务请求，正在保留回复 | 实际 MainActivity 的 `stop_task` 按钮，注入触摸 DOWN／UP | 自然绘制的停止状态与同一帧的公开 Window FrameMetrics；不等于物理呈现 |

| 配置 | scope | 每 API | 八档计划 |
| --- | --- | ---: | ---: |
| `pilot` | `busy-stop-pilot` | 两场景各 2 次，共 4 次 | 32 次停止 |
| `formal` | `busy-stop-diagnostic` | 两场景各 100 次，共 200 次 | 1,600 次停止 |

同一 repetition 内执行两个场景，偶数轮为平台／模型，奇数轮反向。固定索引、顺序和数量，不接受任意样本数、不删首轮、不按剩余时间缩短、不重放失败样本后仅保留成功替代项。修复后的运行保留独立源码和分母，不与试跑或旧失败前缀拼接。

按 **API × 场景 × 指标**分别列有效数、中位数、范围和 P95；每个 P95 至少需要 100 个有效原始值，采用 nearest-rank `ceil(0.95 × n)`。试跑不报告正式 P95，浮条场景缺少完整帧指标时保留 unavailable，不能借主页面数据补齐。功能等待上限不是 200 毫秒产品预算；超过参考值时保留并分析，不以放宽或删样本掩盖。

## 停止入口与时钟

停止前核验原任务、实际可见且可用的按钮及其几何位置；测试的被动 OnTouchListener 只记录 UP，并返回 false，不替换生产 OnClickListener，也不自行调用停止。必须有一次实际 UP 到达预期按钮，DOWN／UP 注入结果均保留。

主响应区间从 **UP 注入前的 `System.nanoTime()`** 开始，包括测试注入与输入分发开销；另列 UP 实际到达按钮后的处理区间。注入后的时间不能改作主起点。FrameMetrics 的 VSYNC 与新探针使用单调时钟域；旧 PerformanceTrace 和原屏障字段的 elapsedRealtime 时钟另列，不直接跨域相减。

取消观测时间由默认禁用的有界诊断探针在 `RunControl.cancel()` 返回后、其他停止清理之前记录。它包含取消钩子耗时，是“已观测到失效”的上界，不是执行代次变化的精确线性化时刻。旧 `STOP_EPOCH_INVALIDATED` 保持原有取消及部分清理后的含义，旧 `STOP_UI_APPLIED` 仍只表示状态发布，二者都不能冒充完整帧。

探针只在显式测试会话中启用，绑定原 RunControl 和当前诊断会话，保存固定枚举与有界数字。它不记录真实提示词、模型请求正文或密钥，不改变生产停止、确认或设备提交语义；迟到事件不能写入下一次采样。启用时的时钟读取及有界锁开销属于测试条件，不能据此宣称无探针净成本。`STOP_OWNED_ENTRY` 位于 Controller 锁内，只代表已取得原任务的停止阶段，不是最初函数入口；主 UP 前起点仍保留锁等待。

## 已提交动作、迟到回复和资源归属

平台场景分别保存：**屏障进入／解除阻塞、目标点击效果写入、实际平台调用进入／返回或异常、原线程提交凭据结算**。原 SlowReadBarrier 的 returned 只代表屏障等待结束，不能写成平台调用返回。

停止时必须仍有一个原平台调用在途；取消后原票据和服务调用槽不得提前释放。显式释放屏障前，用独立适配器验证调用槽仍忙且没有提交新动作；释放后允许已经进入系统的点击完成一次，最终 Fixture 计数为 1。原 owner 的后续请求必须拒绝，原派发计数保持 1，旧结果不能恢复 Controller 或改写已冻结的用量与任务结果。

模型场景的派发数保持 0。停止后再释放服务器回复；客户端可能已断开，服务端写入失败属于允许的传输结果，但不能据“写入成功”断言客户端采用了回复。原 Controller、网络 callable 与关闭连接工作分别完成有界排空，不能用被取消 Future 的 `isDone()` 冒充工作线程已经退出。排空和补充安静观察均位于停止响应测量窗之外，下一次采样必须等待清理结束。

两场景分别保留原任务、代次、派发及请求计数、冻结结果和真实阶段时间；汇总断言不能替代原始快照。目标效果、平台接受和 Controller 任务结果分别记录，停止不承诺撤回此前已交给系统的动作。

## 主页面的自然停止帧

在 UP 前注册公开 Window FrameMetrics，确认真实 MainActivity 已在前台、有焦点、启用硬件加速，并取得自然运行状态基线。保留生产 `FLAG_SECURE`，受保护截图记录 blocked，不清标志换取截图或录像。

冻结输入之后**首次**自然 OnDraw 中可见的原任务停止状态：状态文字为“已停止”、运行按钮隐藏、开始按钮可见。通过一次队首 post-traversal 回调读取该次 drawingTime，与原 FrameMetrics VSYNC 的毫秒部分唯一关联；缺失、歧义或失配均失败，不能换用后一个更快或更容易匹配的停止帧。不得调用 invalidate／postInvalidate 制造替代绘制。

HWUI 完成端点为原始 `INTENDED_VSYNC_TIMESTAMP + TOTAL_DURATION`，FrameMetrics 回调收到时间单列；不把回调、OnDraw CPU 片段或状态发布时刻作为完整帧端点。API 30 不保证该端点包含 GPU 完成，所有 API 都不等于实际屏幕 present。GPU／DEADLINE 不支持或未知值保留 unavailable。

候选帧、目标水位、报告丢失、溢出和排空均有界且可复核。已经确定不可能属于目标的旧报告可单列计数，不能偷偷删除目标、清零丢失计数，或让固定缓冲区形成未声明的响应时限。首个停止帧一旦冻结，后续绘制不得替换它。

## 容量、失败与验收

逐次停止写入独立分片，根报告仅引用完整持久化前缀，并绑定字节数与 SHA-256。根报告初始为 incomplete；固定计划、各次必需证据及最终环境恢复全部通过后才能标记 passed。中断、超时和失败前缀如实保留，未取得证据的后缀仍在计划分母中，不能推断全部未执行。

根报告上限 64 KiB、宿主 capture 上限 16 KiB、每分片 32 KiB、每 API 8 MiB。capture 只绑定根文件，全部分片由根引用绑定，避免重复保存 200 份引用。整批继续使用既有 64 MiB 共享归档上限；实施中核验最大序列化布局及真实字节数，不以每档各自低于上限替代整批检查。文件提取采用一次有界归档传输，拒绝路径逃逸、链接、重复、缺片、孤儿文件和来源或语义不符。

容量回归使用实际 schema、19 位数字、128 条 trace、16 条探针及最大字符串逃逸：平台与模型分片分别为 29,092／29,562 字节，200 条引用与最大设备字符串的根报告为 47,937 字节，root-only capture 为 818 字节。按各文件硬上限估计，八档共 53,084,160 字节，仍为普通截图及其他附件留出 14,024,704 字节；归档仍须检查实际共享总量。这些是解析器容量测试，不是设备结果。

正式专项 watchdog 为 2,400 秒、设备内采集上限 2,300 秒、设备作业上限 55 分钟；试跑 watchdog 为 1,200 秒、作业上限 35 分钟。先用试跑实测时间和容量判断正式计划可行性，不在运行中缩减分母或扩大单个失败样本的等待。

完成条件是同一固定源码的正式八档全部原始数据、分场景样本数、真实繁忙条件与触摸入口、停止后零新增派发、原工作线程及资源归属、主页面首个停止 HWUI 帧、来源链和环境恢复全部通过，且统计独立复核一致。设备用例通过但必需采集无效时，专项仍必须失败。此完成范围为上述两种受控繁忙诊断，浮条实际合成呈现、持续复杂满载和真机发布预算继续另行验证；原 273 用例完整 API 矩阵不随本专项关闭。

录像另用 API 35 的一次平台在途调用演示，保持安全窗口，不在正式采样期间录制，不将录像样本计入正式分母。录制失败保留原始记录且不阻塞功能结果，不反复补录掩盖失败。
