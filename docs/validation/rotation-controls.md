# 真实旋转后的待确认动作与控制入口

本模块验证[设计规则 R2/R8](../DESIGN_RULES.md)中的一项模拟器行为：真实横竖屏配置变化后，不沿用旋转前的设备动作；当前控制入口仍可用。以下合同先于设备测试声明，结果取得后单独追加。工程检查点不因新增用例或编译通过而完成。

## 固定范围

- 专用合成 x86_64 模拟器，API30、31、32、33、34、35、36、37.0，共八个固定组合；失败、未执行、缺失及跳过保留在分母。
- 固定方法：`AgentControllerInstrumentedTest#realRotationRejectsOldApprovalAndKeepsControlsReachable`。`rotation-diagnostic`仅选择此方法，专项八项不替代同一源码的完整回归。
- 使用真实 `AgentController`、默认加密配置、本地合成 HTTP 模型和 Fixture；不使用真实模型、个人资料、账号或真机。

## 验证步骤

1. 保存原系统旋转设置及实际显示方向，建立真实竖屏基线；准备请求合成编辑框输入的真实任务并等待当前审批。
2. 记录原任务、执行代次、审批标识、控制窗及按钮实例，确认没有设备派发或已接受写入。
3. 单次请求横屏并等待平台实际方向、显示几何和服务配置生效；不以模拟配置回调或发送广播代替真实旋转。
4. 核对旧控制窗失效、旧按钮引用不能操作新窗口或原任务；核对横屏当前控制条与按钮位于实际安全区域、触控尺寸满足48dp。
5. 通过当前可见确认按钮尝试批准旋转前的动作。执行器必须报告明确未提交的 `STALE_OBSERVATION`，原动作不能派发；模型只能基于新观察提出新审批，不能重放写操作。
6. 通过当前横屏控制条暂停并停止任务，核对执行代次失效、审批清除、任务终止和零派发。再次使用旧审批不能恢复任务或新增模型请求。
7. `finally` 中停止及清理任务，恢复原系统设置和实际方向；失败先记录有界诊断及可采集的合成界面证据，清理失败也保留为失败。

按钮调用使用实际已安装的View监听器，并配合窗口、布局和尺寸检查；不将 `performClick()` 称作物理触摸命中验证。旋转可能重建Fixture，因此界面计数不变不能单独证明没有写入，必须同时核对原任务派发计数及模型收到的结果。产品安全窗口保持启用，受保护或无法取得的截图如实记录。

## 当前状态与后续边界

用例与专项归档接入已实现，本地420项脚本检查通过，零跳过；包含真实SDK的APK预检夹具。新增Android用例在JDK17/SDK35下编译通过，核心JUnit333/333通过；应用JVM单测任务为NO-SOURCE，不算测试通过。设备结果尚未取得。完整回归按同一源码独立执行；操作录像使用既有普通Fixture流程，不代替旋转专项。主Activity旋转草稿、多窗口/PiP、全部显示方向和导航模式、真实读屏、厂商系统、性能预算与真机分别待验证。

本次新增一个Android用例，预定完整回归为271项/API×8＝2168项；原24b9的270项/API结果保持原源码标记。专项只验证旋转这一项，不能用8/8推算2168项通过。


## 首轮失败与测试目标调整

原源码 `a6112fe73a094735168a4e751ecb790ffb3ce7f7` 的 [40816128028](https://github.com/ecojust/Agent-OS/actions/runs/40816128028)为 **0/8通过、8失败**；[原始归档](../../screenshots/40816128028-1/manifest.json)保留63份载荷、811914字节和31张实际PNG，零跳过或缺失。文件摘要和PNG解码已复核；专项没有运行性能探针，八份invalid采集状态不算性能通过。

[API35原始诊断](diagnostics/rotation-40816128028-api35/)证明实际旋转后的旧计划被明确拒绝为未提交的 `STALE_OBSERVATION`，任务派发0；随后原 `REJECT_CLICK` 合成模型要求读取横屏可视区域外的 `counter_value`，因此整个用例仍失败。修正采用独立 `ROTATION_INPUT` 场景，选择两种方向都可观察的 `edit_value`，提出但不执行输入，结束时核对原编辑文本。旧计数器场景及产品实现不改；仍要求严格未提交旧结果后才重新观察和规划，原派发、审批、窗口、接管及恢复断言不放宽。现有规划器回归增加“只有编辑框可见”的正例和未知/已接受写结果拒绝，不增加方法或改变271项分母。首轮合同与结果保留，不能将新的目标契约通过写回旧源码。

[API30独立原始诊断](diagnostics/rotation-40816128028-api30/)确认在`system_rotation`阶段等待当前无障碍审批窗口超时，派发0、模型请求1，截图已为横屏。原日志不足以区分本地身份与平台缓存未就绪，不宣称已证明缓存根因。测试现只在API30的竖屏截图之后、实际旋转之前重新应用UiAutomation原有ServiceInfo，沿用既有字体测试的同进程节点缓存准备；不修改服务声明、原五秒窗口等待、观察校验或执行保护。失败时额外保存至多16个窗口及本地身份、布局、按钮状态等有界元数据，不采集页面正文、不刷新或重试失败断言。

首轮源码的普通API35录像另已归档，36.082秒、428037字节，使用本地合成模型并保留安全窗口标志，不运行旋转用例，不替代0/8结果。修正源码设备复测与新录像仍待执行。
