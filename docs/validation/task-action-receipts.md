# 本次任务操作回执验收

本模块落实功能计划3.1、3.5和设计规则R4的结果区分：本机提交、系统接受与业务目标验证分别记录。它不开放新工具、权限或自动重试，也不将模型最终报告当作实际完成证据。设备结果在同一源码实际回归并归档后登记；当前仍待执行。

## 固定交付范围

- 只记录原任务执行通道中的六种既有写工具：`launch_app`、`click`、`type_text`、`scroll`、`back`、`home`。记录从首次准入到实际返回，重复调用命中旧账本不会产生新的动作记录。
- 回执仅含本地序号、代次、单调耗时、固定动作与状态、白名单错误码。任务标识仅用于本机归属校验，不展示；没有参数、输入、包名、页面或模型文字、地址、密钥及完整工具JSON。
- 缺失、空值、类型错误或矛盾的提交/接受字段不能建立肯定结论，`ok`也不能证明系统接受。中断没有最终回执时明确保留未知；目标验证只有未验证或未知，不生成已完成结论。
- 当前任务最多保留最近200项并报告省略数；纯内存、不可变快照，不建立历史数据库。暂停继续保持同一任务，停止、配置失效和结束冻结未决项；清空与替换后迟到工作线程不能写回新任务。
- 原生查看页保留`FLAG_SECURE`，禁止View状态持久化，只读且按用户请求打开，不触发设备读取、网络、操作重放或控制窗额外发布。关闭、离页、清空和替换沿实际生命周期处理，不提供复制或导出入口。

## 在设备运行前确定的验证范围

核心测试验证真实Dispatcher结果映射、首次/重复调用、未知结果与中断、旧代次、缓冲上限、不可变快照及字段脱敏；使用本地HTTP的Runner测试验证实际监听器交接，不以伪造UI文本替代链路。

Android仪器测试使用真实Controller、本地合成HTTP和Fixture应用：拒绝操作仍有未提交回执，系统接受的真实写操作保持目标未验证；检查冻结查看页、安全标志、零额外请求/派发/发布，以及停止、清空、替换和离页后的旧记录隔离。测试不清除受保护页面安全标志，不要求产生该页面PNG；未尝试采集与测试跳过分别记录。

新用例加入既有八档完整矩阵，不另建缩小分母的验收工作流。普通操作录像继续展示既有Fixture与控制窗，不展示受保护回执页面；录像不能代替独立回执断言。真机、真实模型、常用应用全面兼容、性能预算与ROM继续单独验收。
