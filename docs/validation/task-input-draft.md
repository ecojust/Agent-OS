# 任务输入与页面重建的生命周期隔离

本模块落实[设计规则R6](../DESIGN_RULES.md#r6-数据密钥与清理)的任务内容清理要求，并保持原有内存草稿重建行为。此前任务输入只作为字符串保存在`UiDraft`中：新Activity的配置读取如果晚于任务结束或用户清空，仍可能把旧目标重新填回输入框。它不会自动重新执行，但与明确清空和结束后的输入清理不一致。

## 行为范围

- Controller使用进程内对象身份标记任务输入的生命周期，快照同时包含实际运行状态；不复用任务执行代次，不保存或导出该标记。
- 任务实际准入、停止、配置失效和结束时更换标记；成功清空即使面对已经为空的历史也更换。暂停和继续保持同一输入生命周期，被拒绝的旧任务回调不能使新任务标记变化。
- Activity持续记录当前输入所绑定的标记。后台页面错过任务结束或清空通知后，不能在保留草稿时把旧文字重新绑定到新标记。
- 重建后的迟到读取只有在原草稿、当前页面和Controller标记及运行状态一致时才恢复任务文字。显式清空另撤销本页面尚待恢复的任务输入，不依赖Controller已完成资源清理。
- 同一资料中的模型、密钥、回复上限和任务预算草稿沿原路径保留。历史任务结束后用户新写的未提交任务，在没有新任务、结束或清空边界时仍可正常保留。
- 不自动保存草稿、恢复任务、发送模型请求或写入历史文件；安全窗口与禁止View状态保存保持。

## 验证范围

三项设备回归使用真实Start按钮、实际本地HTTP任务、Controller终态和实际Activity重建；只在新Activity已经存在的存储工作队列中加入有界测试等待，使迟到读取时序可重复，不替换生产配置读取或伪造输入标记。

| 用例 | 断言边界 |
| --- | --- |
| 实际任务结束先于重建后的配置读取 | 真实界面启动、确认本地HTTP连接并取得实际待审批动作；返回同一页面后重建，阻塞替代页面的存储队列，点击拒绝使原任务以`FAILED/PERMISSION_DENIED`结束。旧草稿对象此时仍在等待绑定；释放读取后目标保持为空，原任务零设备派发，配置未被额外保存 |
| 空历史清空与后台旧页面 | 后台页面实际停止监听后清空空历史，直接调用真实保留回调确认旧文字不能获得新身份；回到同一页面填写草稿，再实际重建并连续两次点击清空。迟到读取只能恢复模型与预算草稿，不能恢复目标，历史始终为空且没有任务或HTTP请求 |
| 已结束历史之后的新草稿 | 实际拒绝任务结束后，用户填写新目标和未保存的模型、预算文本；实际重建后原样恢复，保留原已结束任务记录，不额外保存、启动或请求模型 |

预算草稿使用含前导零的原始文本，与保存后的规范化数值分别核对。所有有界等待在清理时释放，实际旧、新页面及各自工作队列先关闭，再还原测试配置与服务状态。

本轮使用明确的`Activity.recreate()`验证重建时序，不把它称为真实设备旋转。后台旧页面的保留回调若由测试直接调用，也与平台实际触发的重建分别记录。受保护任务和配置页面不尝试截图，保存逐案结果及未采集原因，不新增安全窗口例外。
