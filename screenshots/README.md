# 测试截图记录

从本轮开始，Android 界面测试保存实际模拟器截图与逐项清单，按 CI 运行编号和 attempt 分目录，并提交到仓库。旧测试未采集的截图不补画。

- 截图来自独立合成测试应用、明确为空配置的 Agent OS 测试界面，或已冻结官方样本内的指定合成数据场景；禁止真实账号、密钥及用户页面。官方样本另行核对已安装身份、前台与保护状态。
- 产品的安全窗口设置保持不变；如拍摄空白控制台展示图，只有测试代码临时调整窗口标志，并在 `finally` 恢复。
- 安全窗口、不可观测页面或采集失败明确记录 `blocked` / `fail`，不把黑屏当成功截图。
- JVM、加密存储等无界面测试记录其结果和没有截图的原因，不使用无关屏幕冒充证据。
- 测试通过与截图成功分别记录；一个 PNG 不能证明应用兼容或任务完成。

每批记录应包含源码提交、系统 API、测试运行链接、时间、测试名称、结果、截图路径及采集状态。模拟器结果与真机验收分开统计。

常规归档仍使用 `publish-evidence.yml` 的 `mode=master`。开发分支需要显式选择 `mode=review_branch`，从同一 `agent/*` 分支启动归档，并提供 `run_id` 和精确的 `expected_source_sha`；只接受本仓库该分支手动运行的 `android.yml`。归档核对源运行、attempt、任务、产物来源及上传时间，只写独立 `evidence/<run>-<attempt>` 分支。清单明确标为开发分支待复核证据，不提升主线验收状态，也不执行被归档源码或产物。

`demos/<run>-<attempt>` 保存整体操作演示与录制清单。视频来自专用模拟器的实际操作，单个文件小于 100,000,000 字节；模型回复如来自本地测试服务，会明确标注。录制不关闭安全窗口保护，不包含密钥配置或图片审阅页面。视频、测试结果和捕获成功分别记录，失败和受保护画面不冒充可用演示；README 只链接已经验证的可播放录像，并保留其真实源码版本。

`third-party-<run>-<attempt>` 是[独立第三方应用开发探针](../docs/validation/third-party-smoke.md)的证据，与执行器合成应用矩阵分开统计。安装成功、服务绑定、日常算术流程和截图各自记录；辅助器失败和未执行的流程不能标为应用兼容通过。
